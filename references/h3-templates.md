## v5の骨格の考え方（情報インベントリ方式）

**スロットを埋めるのではなく、持っている情報を棚卸しする。**

1. 先に「伝える事実」を列挙する（数字・固有名詞・条件で書けるものだけ）
2. 各事実を「文／ul／table」のどれで出すか宣言する（パーツ設計）
3. 文数は事実の数で決まる。**事実が2つなら2〜3文でよい**（上限目安4〜6文・下限なし）
4. 言い換え・当たり前の総括・「〜が魅力です」等の埋め文は書かない

### パーツ設計の判断基準

| 情報の形 | 使うパーツ |
|---|---|
| 3項目以上の列挙（確認項目・対処法・選択肢） | ul（直前に誘導1文） |
| 対になる比較（向き/不向き・コース×価格・冷蔵/冷凍） | table（2列以上） |
| 数値が2軸以上（サービス×料金×送料） | table |
| 事実1つ＋理由 | 文（PREP） |

※ 表・ulで出した数字・項目を本文で言い直さない。

### 具体例（ウォーターサーバー おすすめ・実物）

```
「ウォーターサーバーのおすすめが多すぎて、どれにすればいいか分からない」
```

## 選び方系 H3 のテンプレート（PREP法 + パーツ設計）

═══════════════════════════════

正本：writing-manual.md §3（H3の中身の作り方）

### 骨格の型

```
【H3骨格】id="{id}" {選び方の見出し}
■ 伝える事実
  1. {比較・確認の判断基準（何をどう比べるか）}
  2. {なぜその基準か（失敗パターン・数字）}
  3. {確認する具体的な項目や手順（あれば）}
■ パーツ設計
  - 事実1・2 → 文
  - 事実3 → ul（確認項目が3つ以上あるとき）
■ 結論(1文目): {判断基準を1文で。KWまたは複合KWを自然に}
■ strong締め: {任意。具体的な確認方法・行動が書ける場合のみ}
■ 共起語: {このH3で入れる共起語}
```

### 文章化の例：「送料込みの月額費用で比較する」

```html
<h3>送料込みの月額費用で比較する</h3>

食材宅配サービスの料金は、商品代金に送料や年会費を足した月額の総費用で比べてください。

送料は注文金額や配送エリアで変わるサービスが多く、商品代金が安くても総額では割高になるケースがあるからです。

比べるときに確認する費用は次の通りです。

<ul>
<li>商品代金</li>
<li>送料(注文金額・地域別)</li>
<li>年会費・入会金</li>
</ul>

<strong>公式サイトの料金ページで定期コースの送料条件まで確認すると、月額の総費用で比較できます。</strong>
```

**ポイント**：1文目が結論／2文目が理由（「〜からです」で接続）／列挙はulへ／strongは具体的な行動。ulの項目を本文で言い直していない。

## メリット系 H3 のテンプレート（PREP法）

═══════════════════════════════

### 骨格の型

```
【H3骨格】id="{id}" {メリットの見出し}
■ 伝える事実
  1. {読者の生活で何がどう変わるか（具体的な場面・数字）}
  2. {なぜそうなるか（サービスの仕組み）}
■ パーツ設計
  - 原則は文。効果が複数の場面に及ぶときだけul
■ 結論(1文目): {効果を具体的に。KWまたは複合KWを自然に}
■ strong締め: {任意。読者の生活変化 or 数字で裏付けられる価値}
■ 共起語: {このH3で入れる共起語}
```

### 文章化の例：「買い物の往復時間がなくなる」

```html
<h3>買い物の往復時間がなくなる</h3>

食材宅配サービスを使えば、スーパーへの往復と食材選びにかかる時間をまるごと省けます。

注文はスマホで5分ほどで完了し、指定した曜日に自宅まで届けてもらえます。

週2回の買い物に往復1時間かかっていた場合、月に約8時間が浮く計算です。

<strong>買い物にかかっていた時間を、家族と過ごす時間や自分の趣味に使えるようになります。</strong>
```

**ポイント**：3文＋strongで完結。効果を「月に約8時間」と数字にしている。同じ効果を言い換えた4文目を足さない。

```html
<h3>少量注文だと送料の負担が大きくなる</h3>

一人暮らしで少量だけ注文すると、送料の割合が高くなり1食あたりの金額が上がります。

</ul>
```

## 口コミ解説 H3 のテンプレート（口コミ・評判記事用・v5新設）

═══════════════════════════════

正本：writing-manual.md §6（口コミの書き方）

### 骨格の型

```
【H3骨格】id="{id}" {口コミの見出し（例：量が少なめで物足りないとの声）}
■ 引用する口コミ: {実在口コミのURL・出典（原文ママ・改変禁止）}
■ 伝える事実（⚠️ 口コミの言い換えは事実に数えない。新しい情報だけ）
  1. {なぜそうなるか（原因・仕組み・数字）}
  2. {どうすればよいか（対処・選び方・具体的なコース名等）}
■ パーツ設計
  - 対処法が2つ以上 → ul
  - 「合う人/合わない人」 → table
■ 導入1文: {何についての口コミかを示す}
■ strong締め: {任意。対処・数字を含む文に付けられる場合のみ}
```

### 文章化の例：「量が物足りないとの声」

```html
<h3>たくさん食べる人には量が物足りない</h3>

量については、味は良くても物足りなさを感じたという口コミがあります。

<blockquote>（実在口コミの原文ママ）
<cite>— 投稿者（@handle）YYYY年M月D日のXより
出典確認元：<a href="URL" target="_blank" rel="nofollow noopener">X</a></cite></blockquote>

お弁当はカロリーと塩分を計算して作られているため、よく食べる方や若い男性には少なく感じる場合があります。

量が足りないときの調整方法は次の通りです。

<ul>
<li>ご飯や汁物を自分で足す</li>
<li>おかず5品の「いつでも五菜」を選ぶ</li>
<li>単品メニューを組み合わせる</li>
</ul>
```

**ポイント**：解説は「原因1文＋対処ul」だけで完結。
**書いてはいけない文**：「物足りないと感じる方もいます」（口コミの言い換え）／「この口コミのように〜する方もいます」（blockquoteの再説明）／「食べ応えを重視する方は工夫が必要です」（対処ulの言い換え総括）。

## サービス紹介系 H3 のテンプレート（4〜5文・180〜310字 + 訴求社strong価格訴求文）

═══════════════════════════════

正本：article-structure.md §4

> **2026-08-06 修正**：旧FAB法（Feature/Advantage/Benefitの3段落分離）は廃止。article-structure.mdが製本13記事を実測した結果、Advantage/Benefitの分離は存在せず実物は4〜5文・180〜310字だった。

### 構成

```
【サービス紹介H3】（骨格不要・テンプレコピペ）

1. _table登録済みサービス → [サービス名_table] をH3直下に1行（画像＋テーブル直書き禁止）
   未登録サービスのみ → service-info.md から画像＋テーブルHTMLをコピペ
2. 紹介文（4〜5文・訴求社250〜310字／非訴求社180〜230字）：

1文目: <strong>〇〇は、＜特徴＞の＜カテゴリ＞です。</strong>（メインKWか複合KWを入れる。特徴は1つに絞る）
2文目: 他社との違い（テーブルの数字を同じ角度で繰り返さない）
3文目: 読者の生活でどうなるか（「温めるだけ」→「調理や片付けの手間を省きたい方に向いています」）
4文目（訴求社のみ）: <strong>価格・割引のstrong</strong>（具体的な金額がないときは置かない）
  - 「〇〇%OFF」と書いた同一文内に適用条件を併記
5文目: 任意の補足1文

CTA（service-info.mdからコピペ・最終行に1つ）
```

### 具体例（製本542・実物）

```html
<h3 id="1a">ライフミール</h3>

[lifemeal_table]

<strong>ライフミールは、東証スタンダード市場上場の株式会社シルバーライフが運営する宅配冷凍弁当サービスです。</strong>

管理栄養士監修のもと、糖質30g以下・食塩相当量2.5g以下に調整された100種類以上のメニューを取り揃えており、和・洋・中と豊富なバリエーションから好みのメニューを自由に選べます。

また、電子レンジで約5分温めるだけで主菜＋副菜が揃った食事が完成するため、忙しい日でも手軽に栄養バランスの取れた食事が楽しめます。

<strong>定期購入なら1食あたり382円〜と、宅配冷凍弁当の中でもトップクラスのコスパを誇ります。</strong>

さらに、初回限定で10食セットを1食190円で試せるお試しプランも用意されており、気軽にスタートできるのも魅力です。

[lifemeal]
```

### 具体例（非訴求社・_table未登録）

```html
<h3 id="8a">nosh（ナッシュ）</h3>

（service-info.md のテーブル・画像をコピペ）

<strong>noshは、メニューを1食ずつ自分で選べる冷凍宅配弁当です。</strong>

全メニューが糖質・塩分に配慮した基準で作られており、新メニューが定期的に追加されます。

食べたいものだけ選べるため、苦手なおかずが届く失敗を避けやすいです。

[btn href="https://nosh.jp/" class="raised main-bc strong" target="_blank" rel="nofollow"]noshの公式サイトはこちら[/btn]
```

### チェックポイント

- [ ] 1文目のstrongに複合KW（「宅配弁当」「食材宅配サービス」等）が含まれている
- [ ] 1文目の特徴が1つに絞られている
- [ ] テーブルに記載した情報を本文で同じ角度で繰り返していない
- [ ] 書き出しパターンが同じ記事内で3種類以上ある（15社なら同一パターン最大5社）
- [ ] 訴求社の4文目は具体的な価格・割引があるときのみ／非訴求社にはなし
- [ ] 利用シミュレーション文（「夫婦で1日1食ずつなら〜」等）を書いていない
- [ ] CTAが最終行に1つだけ

### 書き出しパターン（最低3種類）

```
パターンA: 「〇〇は、＜特徴＞の冷凍宅配弁当です。」
パターンB: 「＜特徴＞を提供する〇〇は、」
パターンC: 「〇〇は、＜特徴＞を届けてくれる食材宅配サービスです。」
パターンD: 「〇〇は、＜特徴＞に特化した宅配弁当です。」
```

## FAQ H3 のテンプレート

═══════════════════════════════

正本：article-structure.md §6

### 構成

```
<h3>質問文（「〜ですか？」「〜ありますか？」「〜ますか？」で統一）</h3>
[1文目] 回答の結論
[2〜3文目] 補足・具体的な情報（2〜3文で完結）
```

### ルール

- 本文で既に扱った内容の焼き直しは禁止
- サジェスト・PAA・競合のFAQから、本文で未対応のニーズを選ぶ
- 知恵袋・5ch等のユーザー投稿型サイトには一切言及しない（article-structure.md §6）
- 質問文に番号プレフィックス（「Q1：」等）を付けない
- FAQのH2直下に質問一覧のolを置かない
- 4〜6問（article-structure.md §6）

### 具体例

```html
<h3>一人暮らしでも食材宅配は元が取れますか？</h3>

食材を使い切れれば、一人暮らしでも元が取れます。

冷凍保存できる食材や少量パックのコースを選ぶと、食材を余らせずに使えます。

自炊の光熱費や外食費を含めた総額で比べてみてください。
```

## まとめ H2 のテンプレート

═══════════════════════════════

正本：article-structure.md §7

> **2026-08-06 修正**：旧「3〜5文」は廃止。article-structure.mdが製本13記事を実測した結果、実物は5〜6文・strong2箇所（結論＋行動促し）だった。

### 構成

```
[1文目] 結論の前提となる事実
[2文目] <strong>記事の結論を1文で要約（メインKW含む）</strong>
[3〜4文目] 補足（読者の判断基準・注意点）
[5〜6文目] <strong>具体的な次のアクション</strong>（必ず「〜してみてください」「〜決めてください」で終える）
```

- **5〜6文**。strongは記事の結論と行動促しの2箇所
- 「いかがでしたか」「参考になれば幸いです」は使わない
- まとめH2の見出しは `まとめ：〜` の形。他のH2と同じ文言にしない

### 具体例（製本889・実物）

```html
<h2>まとめ：ヨシケイの料金を確かめて自分に合うコースを選ぼう</h2>

<strong>ヨシケイの料金はコースと人数で1食約350〜1,000円、平日夕食を毎日使うと2人で約3万円・4人で約4〜5万円が目安です。</strong>

高く感じても、買い物の手間や食材ロスが減るぶん、合計の食費は自炊と大きく変わりません。

まとめ注文・多人数注文・NICOSカードを使えば、料金をさらに抑えられます。

<strong>まずはお試し5daysを1食300円で頼んで、味と量を確かめてから自分に合うコースを選んでください。</strong>
```

## 全テンプレート共通のチェックリスト

- [ ] 1文60字以内・一文一改行（「。」の直後に空行）
- [ ] 1文ごとに検算した（消しても意味が変わらないか／具体か／中学生が一読で分かるか／既出と重複しないか）
- [ ] 3項目以上の列挙・対の比較を文のまま流していない（ul/tableへ）
- [ ] 専門用語の初出時にカッコ補足（article-structure.md §11）

- [ ] 法令セーフ変換表10パターン適用済み（writing-manual.md 付録：法令セーフ変換）
- [ ] ミニ免責は本文で繰り返さず末尾に集約（writing-manual.md §8）
