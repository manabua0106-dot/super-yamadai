# 口コミ取得スキル（kuchikomi-shutoku）

**正本**：`.claude/rules/writing-manual.md` §6（口コミの書き方・ルール）。本スキルは**取得手段**（どうやって一次投稿を見つけて裏取りするか）の実行手順だけを扱う。§6のルール（実在の公開口コミのみ・捏造禁止・出典制限・cite形式）は本スキルが上書きしない。

**大原則**：X本体でのキーワード検索はほぼ機能しない（後述）。**発見は競合記事・アグリゲーターサイト経由、本文確定はX公式の埋め込み用CDN経由**という2段構えが実質唯一のルート。2026-08-10、過去セッション履歴を実測して本スキルを起こした（syndication CDN呼び出し89件・r.jina.ai経由53件・競合記事の埋め込みURL列挙15件超の実績あり）。

---

## できないこと（先に把握しておく）

- X本体でのキーワード検索（`site:x.com`のWebSearchは該当ツイートがヒットしないことが多い）
- Xのハッシュタグページへの直接アクセス（402・課金要求）
- `publish.x.com/oembed`（402）
- みん評(minhyo.jp)の直接WebFetch（403）
- 楽天レビュー(review.rakuten.co.jp)の直接WebFetch（403）

---

## 手順（この順で試す。①〜④を試してから「取得不能」と結論づける。1回失敗して諦めない）

### ① 競合記事に埋め込まれたX投稿URLを辿る（最有効・最優先）

口コミ・比較・体験談系の競合ブログをWebFetchし、埋め込み投稿URLを列挙させる。

```
WebFetch(
  url: "{競合記事URL}",
  prompt: "この記事に埋め込まれている、または引用されているX（旧Twitter）投稿のURL
（https://x.com/.../status/数字 または https://twitter.com/.../status/数字 形式）をすべて列挙してください。
特に{狙いたい属性・感情語（例：量が少ない・高い・便利・時短）}に関する投稿を優先。"
)
```

- 対象記事は「{ブランド名} 一人暮らし」「{ブランド名} 口コミ」「{ブランド名} 評判」等のWebSearchで見つける
- 1記事で5〜11件ヒットすることもある
- ここで見つけたURLは①→③の橋渡しに過ぎない。**引用元は必ず③で確定した一次投稿URLになる**ため「同一KWで競合するアフィリ記事を出典にしない」（§6）には抵触しない

### ② X/Twitterドメイン限定のWebSearch（補助）

```
WebSearch(query: "{ブランド名} {感想語} x.com status", allowed_domains: ["x.com","twitter.com"])
```

ヒット数は①より少ない。ハンドル名が分かっている場合や①で手詰まりのときに試す。

### ③ 本文確定：X公式の埋め込み用CDN（①②で発見した全IDに必須）

ツイートID（status以降の数字）が判明したら、必ずこのURLで原文を確定する。ログイン不要・公開JSON。

```
WebFetch(
  url: "https://cdn.syndication.twimg.com/tweet-result?id={ツイートID}&token=a&lang=ja",
  prompt: "このJSONから、ツイート本文(text)・表示名(user.name)・@ハンドル(user.screen_name)・
投稿日時(created_at)を原文ママで抜き出してください。削除済みや取得不可なら「取得不可」と答えてください。"
)
```

- `created_at` はUTC。+9hして日本時間に直す
- **#PR / #モニター / #られしーず等のタグ付き投稿は中立の口コミではないため除外**（景表法ステマ規制）

### ④ みん評・オリコン等アグリゲーターの迂回取得（①②で足りない時）

直接WebFetchは403または文字化けするため、必ず `r.jina.ai` プロキシ経由にする。

```
WebFetch(url: "https://r.jina.ai/{対象URL}", prompt: "...")
```

- 使えるサイト例：オリコン顧客満足度（life.oricon.co.jp）、みん評（minhyo.jp）
- **⚠️ 直接WebFetch（r.jina.aiを介さない）は実在しない口コミを捏造して返すことがある**（2026-07、コープデリで架空の「30代女性…」6件が生成され、再取得したら本文が存在せず捏造と判明した実例あり）。必ずr.jina.ai経由で取得し、**特徴的な一文が再取得でも一致するか確認してから採用**する。要約モデルの出力を原文扱いしない
- 「全件書き出し」は著作権で拒否されることがあるため、話題を絞って数件ずつ依頼する
- 公式アプリのApp Store/Google Playレビューページ（`https://apps.apple.com/jp/app/{アプリ名}/id{ID}`）も一次投稿として使える

## CTA直下の口コミ（横スライド `[X_kuchikomi_slide]`）に使う投稿の選び方

**使い分け・型は `.claude/rules/appeal-ranking.md` が正本。** ここは、どの投稿を選ぶか（2026-10-13・22サービスぶんを集めた実績から）。記事本文の口コミの章（`writing-manual.md` §6）とは基準が違う。

- **3年以内の好意的な個人の投稿だけ**。見つからないときは、古い投稿で作るかをマナブさんに聞く（古い投稿は日付がciteに出る。2026-10-13 タイヘイは3年以内が0件で、2021〜22年の投稿で作ると決めた）
- **「案件でないと確かめられる個人の自発的な感想」だけ**。次は外す
  - 他社を否定的に比べる一文を含む投稿（競合の訴求社を下げてしまう）
  - 末尾に #PR・紹介コードが付くもの
  - ブロガー・ライター名義、レビュー専門、グルメ紹介系のアカウント
  - 同時期・同じハッシュタグの投稿群（未表記の案件の疑い。ステマ規制は2023年10月施行）
  - 公式アカウント、亡くなった家族の話など配慮が要る投稿
- **写真なしを優先**。写真つきは枠が高く（最大約660px）、スワイプで枠の高さが変わる瞬間に表示がガタつく（CLS）。2件の高さの差が小さい組み合わせにする
- **「純粋なマイナス評価」は入れない**（`appeal-ranking.md`「CTAの口コミは良い評価が主」）。「量が少ない」など読者が気にする点に触れたうえで満足している投稿は可
- **調査担当（サブエージェント）の報告は候補として扱う**。本文・日付・返信かどうかは、③のCDNから自分で取り直す（2026-10-13は111件すべて報告と一致）。同時実行は6本まで
- 本文に `[` `]` `\` `{` `}` が入る投稿は、WordPressが解釈しないよう文字参照にしてからスニペットに入れる
- 検索の制約：GoogleとYahoo!はCAPTCHAで遮断、BingはX投稿を返さない、X本体の検索は不可。新しい個人投稿ほど、競合記事の埋め込み経由では見つかりにくい

## 採用前チェック

- [ ] 本文を改変していないか（要約・言い換え・創作は禁止。原文ママ）
- [ ] citeに確認できた属性以外を付けていないか（ハンドルから年代・肩書きを推測して付けない＝捏造）
- [ ] #PR/#モニター等のステマタグ投稿を除外したか
- [ ] r.jina.ai経由の取得は再取得で本文一致を確認したか（オリコン等の捏造事故対策）
- [ ] lint禁止語が原文に含まれていないか（blockquote内もlintが拾う。含まれる場合は原文を変えず別の声に差し替える）
- [ ] 出典が同一KWで競合するアフィリ記事になっていないか（発見の手がかりに使うのはOK、引用元は必ず一次投稿URL）
- [ ] 良い口コミ・気になる口コミが同数程度になっているか（**記事本文の口コミの章だけ**。CTA直下の口コミ `[X_kuchikomi_slide]` は良い評価が主で、この項目の例外＝`appeal-ranking.md`）

## 出力形式（writing-manual.md §6準拠）

```html
<blockquote>
{本文ママ}
<cite>YYYY年M月D日のXより／出典確認元：<a href="{ツイートURL}" target="_blank" rel="nofollow noopener">X</a></cite>
</blockquote>
```

取得できなかった分は出典名を出さず一般化して書き、「〇件中〇件しか一次投稿で裏取りできなかった」とユーザーに正直に報告する（捏造しない）。

---

## 同時実行の注意

WebFetch/サブエージェントの同時起動は6本まで。過去に10本同時起動でセッション上限に達し全滅した実例がある。多数のツイートIDを裏取りする場合は6件ずつに分けて実行する。
