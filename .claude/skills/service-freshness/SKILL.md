# service-info 鮮度チェック（ヤマダイ）

**目的**：価格改定の見落とし事故（過去事故ログ5「価格改定の見落とし多発」）を執筆前に防ぐ。**このスキルは差分を報告するだけで、service-info.md を勝手に書き換えない**（更新はManabuさん承認後・数値は1:1で扱う）。

## 手順

1. **対象社の決定**：指定があればその社のみ。指定がなければ「次の記事で扱う社」＞「訴求社全社（宅配弁当7社＋食材宅配4社）」の順。全社チェックは Workflow で並列化する（1社1エージェント・5〜10社ずつ）。
2. **公式の現行値を取得**：`.claude/rules/service-info.md` の各社エントリ（費用・送料・お試し・比較テーブル用単価）と、公式サイトの料金・キャンペーンページを突き合わせる。
   - 取得は `curl -s -m 20 "https://r.jina.ai/{公式URL}"` を基本にする（WebFetchのタイムアウト回避。⏱リトライ1回まで）。
   - 取得できない項目は「取得不可・要手動確認」と明示する（推測で埋めない）。
3. **差分表を作る**：社名／項目／service-info.mdの値／公式の現行値／判定（一致・差分あり・取得不可）。
4. **報告**：`.claude/reviews/鮮度チェック-YYYY-MM-DD.md` に保存し、**チャットにも差分行だけの表を必ず出す**（ファイルリンクだけで済ませない）。差分ゼロなら「全社一致」と1行で報告。
5. **更新はしない**：差分があった社は「service-info.md の更新案」を提示して承認を待つ（承認後に更新→更新日を記録）。

## 注意

- 公式サイトの表現をそのまま転記する（法令セーフ変換は記事側で行う。マスターは事実の記録）。
- キャンペーン価格は「どのページ基準か」を必ずURL付きで記録する（同じ公式でもページで条件が違う実例あり＝feedback_writing 学び46）。
- 実行タイミングの目安：執筆開始前（その記事の掲載社のみ）＋月1回（訴求社全社）。
