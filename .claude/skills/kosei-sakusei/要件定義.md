## 0. この文書について

- **目的**：特定クライアント向けに作り込まれた構成案作成スキルから、クライアント固有の文言・サービス・販促フォーマットを取り除き、どの案件にも転用できる「構成ロジック」と「文言（表現）ルール」だけを抽出。
- **想定展開先**：媒体非依存（自社オウンド／アフィリ比較のどちらでも成立）。直近はアフィリ案件を想定。
- **カバー範囲**：構成案を作るときの「何を・どの順で・どんな見出し文言で組むか」の判断ロジックと品質基準。
- **カバーしない範囲**：案件ごとに異なる販促パーツ・固定数値・実在URL・業界固有ルール（→ §12）。

---

## 1. スキルの目的とゴール

- **やること**：構成案（タイトル・メタ・H2/H3階層・FAQ・リライト時の操作タグ）の作成まで。
- **やらないこと**：本文執筆、媒体固有の販促パーツ中身定義、ペルソナ生成・共起語抽出（毎案件、入力として受領する）。
- **最上位ゴール**：「検索1位を狙える／蛇足・重複なし／ターゲットに直接刺さる王道記事」の構成。以下すべてのルールはこの手段。ルール順守の目的化禁止。SEOが弱くなるならルールを曲げSEO優先。

## 2. 前提・入力（案件開始時に定義するパラメータ）

| パラメータ | 内容 |
|---|---|
| 媒体方針 | 自社オウンド（自社/推し先訴求）か、アフィリ比較（中立比較＋成約導線）か。§6の訴求先の作り方が変わる |
| 対象KW／KW群 | メインKW・サブKW |
| ターゲット情報 | **ペルソナ・共起語/LSI は毎案件、入力として受領**。KWのみ受領時は Phase 0 で仮説生成する（§2.5） |
| 既存記事一覧 | 重複・カニバリ判定用の既存URL/KW（実在するものだけ） |
| クライアント固有ルールの正本 | FBを蓄積した最優先ルール文書の場所 |
| 順位／流入データソース | リライト判定・**カニバリ検知**・SERP観察に使う順位／流入取得元（順位ツール／サーチコンソール／アクセス解析） |

### 2.5 沈黙禁止とヤマダイ運用の上書き（2026-07-02 追記）

- **沈黙禁止**：取得できない欄は「未取得・要手動」と明示する。捏造で埋めない・作業を止めない。
- **ヤマダイ運用の上書き（汎用版との差分）**：
  - ペルソナ・共起語・PAA：依頼シートで受領したらそれを最優先（1:1で扱い勝手に変えない）。**KWのみ受領時は Phase 0（SKILL.md）で仮説生成する**（仮説と明示・断定しない・捏造禁止）。
  - 順位・流入データ：**Windsor（GSC/GA4）・Ahrefs でスキル側が自動取得する**（SKILL.md Phase 0/2）。未接続・取得不能時は Ahrefs 代替→暫定判定で進める。

## 3. 最上位の原則（すべてのルールの上位）

- **原則0：SEOで検索1位を取れるか。** 迷ったら「どちらがSEOで強いか」。ルール順守の目的化禁止。SEOが弱くなるならルールを曲げSEO優先。
- **原則1：シンプルでわかりやすい日本語（SEOを損なわない範囲で最優先）。** 中学生でも一読で理解できることを目指す。やさしい方・短い方・具体的な方を選ぶ。業界語・抽象語・比喩・回りくどさは使わない。1文短く、1見出し＝1つの言いたいこと。**ただし原則0が上位**：見出しの骨格・KW配置はSEOで判断し、平易化は表現・語彙のレイヤーで行う（KWは本文で平易に回収）。
- **原則2：鵜呑みにしない。** 「確定」と言われても懸念・蛇足・重複は提起。第三者レビューも確定方針優先で却下可。
- **原則3：記事内の重複を徹底排除。** 1テーマ1箇所。FAQは本文結論の焼き直しにしない。
- **原則4：1見出し1トピック＝1つの意思決定軸（ただし原則0優先）。** 「と」「・」「かつ」で異種を並べたら分割サイン。粒度は「目的（意思決定軸）が違うか」で判断。H2レベルの原則（H3複数はOK）。※セクションの採否・並び順は競合＋依頼で毎回決める（§6）が、個々の見出しは常に1論点に絞る。
- **原則5：独自性で量産記事に勝つ。** 一次情報（独自調査・実測比較・体験・出典明記）を入れる枠を構成段階で**最低1つ確保**する。競合の焼き直しだけの構成にしない（E-E-A-T）。

## 4. 機能要件：3モード分岐

| 判定 | トリガー | ゴール |
|---|---|---|
| A リライト | 既存記事あり ＆ 順位資産あり（取得可） | 既存資産を最大限残し、変更操作が一目で分かる構成案 |
| B リポジショニング | 既存記事あり ＆ 順位資産ゼロ ＆ 狙うKWの需要が高い | 既存URLを土台に、新KW向けへ全面組み替え（新規に近い作り替え） |
| C 新規 | 既存記事なし or 完全な新KW | リサーチからゼロベースで構成 |

> 判定軸は「既存記事の有無」＋「順位資産の有無」。**順位が取得不能・曖昧なら必ず聞き返す**（§5.3の順位取得と連動）。B/Cの切り分けは §5.2(2) の対処決定木・§5.3のリポジショニング判断と一本化。

## 5. 機能要件：ワークフロー

### 5.1 共通・着手前の精査（鵜呑み禁止）

A KW×内容の整合性／B ペルソナ一致／C 競合差別化／D H3の必要性（水増し削る）／E 訴求順と読者利益／F 記事内・サイト内の重複／**G 記事タイプ×SERP整合（狙う記事タイプが実SERP上位と一致するか）**。
1つでも懸念があれば提起してから着手。

### 5.2 共通・SERP適合性＋重複/カニバリチェック（最初にやる）

**(1) SERP適合性チェック（勝てないKWを弾く）**
- 着手前に実SERPを見て、上位を占める**記事タイプ**（比較記事／公式／EC／知恵袋／動画 等）を判定する。
- 狙う記事タイプがSERPと不一致なら、構成を作り込む前に「別KW・別タイプに寄せる」と提起する（作り込んでから勝てないと気づく事故を防ぐ）。

**(2) 重複/カニバリチェック（強化版）**
- **実データで検知する**：既存記事一覧のKW文字列の近さだけで判断しない。順位ツール／サーチコンソールで「そのKW群で今どのURLが露出しているか」を確認し、既に自サイトの別記事が拾っているKWは新規作成した瞬間カニバる、と判定する。
- **データ源**：順位・流入データは Windsor（GSC/GA4）・Ahrefs でスキル側が自動取得する（§2.5・SKILL.md Phase 0/2。依頼シートで受領した場合はそちらを優先し1:1で扱う）。取得不能・未接続のときは暫定判定で進め、データ確認後に再検討する（止めない・§2.5 沈黙禁止と連動）。
- **SERP同一性で検索意図を判定する**：2つのKWのSERPの顔ぶれが8割方同じなら「同一意図＝1記事に統合すべき」。顔ぶれが違えば棲み分け可能。
- **差別化軸**（棲み分け可のときの切り分け）：想定読者／悩みの粒度／解決策の入口／記事の温度感。
- **対処方針まで出す（決定木）**：検知だけで終わらせず、以下のいずれかを結論として示す。
  1. 新規作成（カニバらない・需要あり）
  2. 既存強化（既存が拾っている・伸ばす方が早い）
  3. 統合・吸収（同一意図が複数URL → 1本化。301・canonical）
  4. 棲み分けリライト（意図は近いが読者/粒度で分けられる）
- §5.3のリポジショニング判断と**一本化**して扱う。
- **棲み分けで新規作成する場合の他社比較ガード**：既存の複数社横断比較記事（例：内部リンクの「お試しセット〇選」）と食い合う「他社比較」セクションは、スペック羅列表を作らず**向き不向きの差分のみ**に絞る。既存記事への内部リンク誘導文（writing-manual §E-7）も貼らない（検索意図も権威も渡さずカニバリを避ける）。
- **単一ブランド指名記事では、他社比較を独立H2にすらしない**（「向いている人・向いていない人」H2の中で一言触れるだけ）。指名読者は自ブランドの購入判断が目的で、他社比較の独立H2は主役ズレ＋カニバリの芽になる。特に配送エリアが排他な生協間（コープデリ／おうちコープ等）は同一読者が片方しか使えず比較の読者利益も薄い。（2026-07 コープデリ ミールキットで確認）

### 5.3 リライト・着手前ゲート（必須）

- **順位取得**（順位ツール→サーチコンソール→アクセス解析）。取得可否を報告。「取得不能」で止めない。
- **順位で分岐**：
  - 上位1〜3位 → 構成順序・既存資産を壊さない。成約動線を確認・補強。ただし「守る＝既存文そのまま流用で新情報ゼロ」は禁止。良い素材は土台に残しつつ本文は書き直し、新規価値H2を最低1〜2本足す。
  - 4位以下・圏外 → 通常のリライト（作り替え）。
  - 曖昧なら確認。
- **リポジショニング判断**：既存URLが順位資産ゼロ かつ 狙うKWの需要が高い → 新規作成より既存URLの全面リポジショニングが有利。根拠を示して確定（§5.2(2)の対処決定木と統合）。
- **仕分け**：残す/動かす/分割/吸収統合/追加/新規作成/表記統一（大前提：むやみに改変しない。SEO1位に必要な改変は許容）。

### 5.4 新規モード

KW受領 → リサーチ（KW分類・競合上位・実需・**実SERPの記事タイプ判定**・**競合H2/H3のクラスタリング＝必須トピック/ギャップ抽出**）→ 検索意図の見当（§6.2の型は見当だけ・構成は決めない）→ **競合集約＋依頼情報を重ねて構成を組む（§6.1〜§6.3・固定パターンに当てはめない）** → 構成出力 → 確定。
※ ペルソナ・共起語は入力として受領（生成しない）。
※ **ペルソナ照合**：受領した入力ペルソナと実SERP上位の読者層がズレていないか確認する。乖離していれば構成を作り込む前に Manabuさんに確認する（SEO優先だが、ペルソナと検索意図の食い違いは放置しない・§5.1B と連動）。

## 6. 構成設計のロジック

> ⚠️ **構成に固定テンプレ・固定の「型」を当てない（最重要）。** ヤマダイの記事構成（H2の並び・セクションの採否）は、決まった雛形では決まらない。**毎回、競合上位記事の構成（§5.2・§6.3）＋ Manabuさんが与える依頼情報（KW・訴求順位・掲載サービス・その他指示）を突き合わせて組む。** 過去記事に共通の並びがあっても、それは「その時の競合環境と依頼でそうなった実例」であり、次も同じにする根拠にはならない。**「前はこうだったから」で構成を固定しない。**

### 6.1 構成の決め方（毎回この順で組む・雛形に流し込まない）

固定の型に当てはめるのではなく、以下の順で毎回組み立てる。**構成決定の"本体"は §6.3（競合逆算）と §5.2（SERP適合性・カニバリ）**。§6.1はその使い方の順序を示すだけ。

1. **検索意図の見当をつける**：メインKWから「比較検討／知識獲得／購入直前」等の方向を掴む（§6.2の型は"意図の見当"にだけ使い、H2の並びは決めない）。
2. **競合上位の構成を集約する**：上位10記事のH2/H3をクラスタリングし、必須トピックとギャップを出す（§6.3）。ここが構成の骨格の出所。
3. **依頼情報を最優先で重ねる**：Manabuさん提供の依頼情報（掲載サービス・訴求順位・KW・その他指示）をそのまま反映する。競合になくても依頼にある要素は入れ、訴求順位は勝手に振り直さない（§I-3準拠）。
4. **読者の意思決定順に並べる**：「何がある?→どれ?→使うと?→注意→残る疑問→行動」の流れが自然になるよう、重複なく（MECE）並べる。並びは競合と依頼から決まるのであって、雛形からは決めない。
5. **蛇足・水増しを削る**：競合が持つからと機械的に足さない。§5.1D・§7・§9で削る。

### 6.2 KW型は「検索意図の見当」だけに使う（構成は決めない）

型は「読者が何を知りたい方向か」の当たりをつける道具であって、**H2構成を決める雛形ではない**。型からセクションを機械的に生やさない。

| 型 | 検索意図（見当をつけるだけ） |
|---|---|
| A 用語・仕組み解説型 | とは/仕組み/違い |
| B 比較・選び方型 | 比較/おすすめ/安い/〇選 |
| C スピード・状況対応型 | 即日/今すぐ/◯◯なとき |
| D 対象者特化型 | 属性・職業・立場KW |
| E 行動・手順型 | 乗り換え/申込/やり方 |
| F 金額・条件特化型 | 具体的な金額・条件KW |

- 実際の見出し・並び・セクションの採否は §6.3（競合逆算）＋依頼情報で決める。同じ型でも競合と依頼が違えば構成は変わる。
- 型は「KW→型」の一方向ではない。実SERPを見て「読者の意図は型Xでなく型Yだった」と**逆算・修正**することもある（§5.2のSERP適合性と連動）。

### 6.3 見出しの網羅性を競合から逆算（構成決定の本体・新規/リライト共通）

- 上位10記事のH2/H3を集約・クラスタリングし、次を仕分ける。
  - **(a) 必須トピック**：多数（目安：上位のうち過半）が持つ → 抜け漏れ禁止。
  - **(b) ギャップ**：誰も十分に答えていない → 差別化H2の種にする。
- ここで出た**必須＋ギャップに依頼情報（訴求順位・掲載サービス）を重ね、読者の意思決定順に並べたものが構成**になる。雛形から生成しない。
- H4を無駄に増やすのでなく、必須の網羅とギャップの独占で勝つ（§7-1・§9テスト4と連動）。
- **参考の勘所（競合次第で変わる目安）**：比較検討KWでは「選び方（判断軸の列挙）」が、俯瞰・分類軸・Howを1つに束ねる中核クラスタになりやすい。分類軸やHowを独立H2に切り出さず選び方のH3に集約すると重複が出にくい。比較表は独立H2にせずサービス紹介H2の直下に内包することが多い。※あくまで目安で、固定ルールではない。
- **参考の勘所（単一サービス・レビュー/ガイド型の目安・固定ルールではない）**：単一ブランド指名KW（「〇〇 お試し」等）の体験レビュー＋口コミ＋ガイド記事は、比較の「選び方→サービス紹介〇選」テンプレを当てない。競合上位（レビュー/ガイド型）に倣い「とは→中身/価格→実食レビュー→口コミ→デメリット→勧誘→お試し後（自動入会・解約・2回目）→注文方法→（薄めの）他社比較→まとめ」のように意思決定順で組むことが多い。体験レビュー（＝一次情報枠）は前〜中盤に、読者の最大不安になりやすい「その後/勧誘/自動入会/解約」は後半に厚く置くと刺さりやすい。※あくまで目安で、競合＋依頼で毎回決める。（2026-07 実地テスト「オイシックス お試し」で確認）
- **指名/単一ブランドのレビュー記事は口コミH2を厚くする（良い3・気になる3が目安・Manabuさん 2026-07）。** 指名KWの読者は口コミ・評判で購入判断するため、良い/気になるが各1〜2本では上位を取り切れない。ただし口コミの「気になる声」は注意点H2（締切・割高・添加物 等）と重複させず、量・メニュー・使い勝手など口コミ固有の角度に振る。**良い口コミ／気になる口コミを別H2に分けて各3〜4本にすると更に分かりやすい**（分けたらH3に「良い口コミ：」等の接頭語は付けない＝見出しの言い換え重複を避ける）。お試しH2は申し込み導線でなく「味・量の不安を確かめて解消できる」フレームで置くと、口コミ・注意点から自然につながる。（2026-07 コープデリ ミールキットで確認）
- **レビュー型の「一次/二次」と複数商品の在庫事前確認（2026-07 実地テスト codexレビューで補強）**：体験レビュー（実食・実測）を一次情報、口コミを二次情報（読者が一次を検証する声）と位置づけ、同じ「量・味」を両方で二重に語らず角度を分ける。紹介する複数商品・コース（例：3種のお試しセット）は執筆前に公式で現行の提供状況・価格を確認し、提供終了・裏取り不能なものは構成から外す（推測で書かない・§F-4）。時期限定の派生版は常時提供版を軸に据え、派生分は末尾免責で担保する。

### 6.4 独自性ブロックの確保（最低1枠）

- 一次情報（独自調査・実測比較・体験・出典明記）の枠を最低1つ、構成段階で確保する（原則5）。
- 「情報の具体性」を一段上げ、競合の焼き直しにしない。出典が必要な数値はハルシネーション禁止・裏取り前提。
- 独自性は「新規H3の水増し」ではなく、サービス紹介の各社紹介文と選び方H3の**情報密度・具体性（送料込み1食あたりの実額比較など）**で出す。
- **差別化の核は「実データで成立するか」を主役確定と同時に検算する。** 差別化軸（例「送料込み実額の表」）を決めたら、その軸が service-info.md／公式の料金構造で実際に表化・数値化できるかを確認する。空振りする軸（例：配送方法で送料構造が違い、片方は自明・片方は都県別で単一額に落とせない）は主役にしない。（2026-07 コープデリ ミールキットで確認）

## 7. 品質要件：見出し設計の鉄則（提示前に全項目チェック）
