## 役割

本文のPREP構造と論理的整合性を検証し、修正案を提示する。
入力は「骨格（箇条書き）」または「完成HTML」のどちらも受け付ける。

## チェック項目

### チェック1: PREP構造（1文目が結論か）

H3の1文目が結論になっているか。背景説明・リスク説明から入っていないか。

- NG: 「食材宅配サービスは、会社ごとに特徴が大きく異なります。」（説明から開始）
- OK: 「お試しセットをいくつか試してみると、自分に合ったサービスを見つけやすくなります。」（結論から開始）

### チェック2: 1文目と2文目の結論方向

1文目と2文目が同じ結論方向になっていないか。

- NG: 1文目「配送エリアが限られているサービスが多いです」→ 2文目「対象外の地域に住んでいると利用できません」（同方向）
- OK: 1文目「配送エリアが限られているサービスが多いです」→ 2文目「公式サイトの郵便番号検索で事前に確認できます」（別角度）

### チェック3: H2の問いとH3の答えの整合性

H2が「選び方」なのにH3が「メリット」の内容になっているようなズレを検出。

### チェック4: 文と文の論理的接続（writing-manual §E-10）

前の文と次の文が論理的につながっているか。

- NG: 「全国配送に対応しています。配送日時の指定も可能です。」（関連が弱い）
- OK: 「全国配送に対応しており、配送日時も指定できるため、ライフスタイルに合わせて利用しやすいサービスです。」

### チェック5: H3末尾の論理（strong締め使用時のみ・v4.1で緩和）

⚠️ **v4.1：strong締めは必須ではない**（writing-manual §E-2）。strong締めを使っていないH3はこのチェックをスキップ。

H3末尾が直前の本文から自然に導ける内容になっているか。本文で述べていない論理に飛んでいないか。

- NG: 「食費が読めるようになると、貯金にまわせるお金も把握しやすくなります」（論理の飛躍）
- OK: 「公式サイトで郵便番号を入力すれば対象エリアかどうか調べられます」（本文の延長）

### チェック5b: 1文目と末尾の角度重複（strong締め使用時のみ）

1文目（PREP結論）とH3末尾がほぼ同じ内容になっていないか。同じ行動を言い換えただけのケースも重複として検出。

- NG: 1文目「管理栄養士が献立設計に関与したメニューが届きます」→ strong「栄養バランスの食事を自宅で手軽に食べられます」（同内容）
- OK: 1文目「管理栄養士が献立設計に関与したメニューが届きます」→ strong「栄養計算にかかっていた時間を自分の休息に使えるようになります」（読者の生活変化に角度変更）

### チェック5c: H3末尾の抽象性（strong締め使用時のみ）

H3末尾が抽象的な感想で終わっていないか。「安心です」「便利です」「うれしいです」「魅力です」「ゆとりが生まれます」は抽象的。

- NG: 「メニュー数が多いサービスを選ぶと安心です。」
- OK: 「メニュー数が50種類以上あれば、週5日利用しても2か月近く飽きずに続けられます。」

また、v4.1で追加されたNG型：
- 「〜という事態を防げます。」「〜を避けられます。」（型にはめた不自然な文）

⚠️ **strong締めを使わない選択もOK。** 自然な流れで書けない場合は、無理に締めずに本文の最後の文で自然に終える。

### チェック6: mybox後の橋渡し文

myboxの直後にマーカーを置く場合、間に橋渡しの1文があるか。唐突にマーカーが来ていないか。

### チェック7: H2導入文の役割（writing-manual §A-3）

- 選び方・注意点 → リスク・必要性から入る
- **メリット** → メリットの予告から入る（リスクから入ると不自然）
- サービス紹介 → 比較の必要性から
- 単なる宣言（「〜を紹介します」）になっていないか

### チェック8: 根拠の具体性（v4.0 新規）

PREP の「R（根拠）」と「E（具体例）」が抽象論で終わっていないか。
各 H3 の根拠・具体例部分に、以下のいずれかが含まれているか：

- 数値（料金・期間・人数・割合）
- 固有名詞（サービス名・制度名・食材名）
- 条件（「〜の場合」等）

### チェック9: H3のボリューム（writing-manual §E-2補足）

各 H3 が 4〜6文以内に収まっているか。超えている場合は、読者の行動に直結しない文を削除するか確認。

### チェック10: 一文一改行チェック（v4.0 新規）

- 1文60字以内か（writing-manual §E-3）
- 「。」の直後に空行があるか（一文一改行）

## 修正案の出し方

```
【論理チェック】チェック{N}
- 箇所: {H3 id} の {1文目/2文目/strong等}
- 問題: {何が論理的におかしいか}
- 修正案: {具体的な修正文}
```

修正案を出す際、他の3チェッカーの観点（重複・鉄の掟・KW特化）に違反していないか自分で確認してから提出する。
