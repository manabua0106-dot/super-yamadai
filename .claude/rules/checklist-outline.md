# 構成案の提示前チェックリスト（記憶に頼らないための1枚）

**使い方**：構成案をManabuさんに提示する**直前に必ず本ファイルを開き、全項目を1つずつ全見出しに当てる**。
lint-outline.sh が機械で見るのは A群だけ。**B群・C群は人が見るしかない**ので、記憶で済ませずここを読む。

> **なぜ作ったか**：2026-08-04、同じ型の指摘を何度も繰り返した。原因は「lintが拾わない項目を記憶で処理していた」こと。
> 覚えている範囲でやると毎回どれかが抜ける。提示前に読むファイルを1枚に固定して、記憶依存をなくす。

## A群：lint-outline.sh が機械検出（実行するだけ）

```bash
bash scripts/lint-outline.sh "articles/{KW}/outline.md"
```

ERROR 0 / WARN 0 になるまで直す。カバー範囲は以下。

- カッコ・記号・感嘆符・疑問符（FAQ質問H3の「〜ですか？」だけ例外／**区切りの `｜` は2026-09-09 に解禁**）
- FAQ語尾の「？」漏れ
- AI臭ナンバリング「○つの」
- 冗長修飾（〜に関するよくある質問／〜で気をつけたい）
- 曖昧名詞（定期→定期便）
- カテゴリA硬語（試算・向き不向き・コスパ・シミュレーション・見合う 等）
- **口コミのメタ記述**（人が多い／と書く人／ほめる／に集ま 等）＝学び58
- **ネガ評価の断定**（帰属表現がないネガ語）＝学び59
- **空見出し**（〜で決まる／〜によって変わる／〜が大切）＝学び60
- **H2の金額詰め込み**（範囲表記・2つ以上の併記）＝学び61
- タイトルの年号・記号・硬語・字数

## A群-2：競合の網羅を機械検算（2026-09-08 新設・実行するだけ）

```bash
# ラッコMCP headline のレスポンスJSONを articles/{KW}/competitor.json に保存してから
python3 scripts/check-coverage.py "articles/{KW}/competitor.json" "articles/{KW}/outline.md"
```

ERROR 0 になるまで対応する。検出は2種類。

- **取りこぼし**：2サイト以上が持つトピックが構成案に1本も無い
- **厚みの不足**：競合が見出し5本以上を割くトピックを、構成案は1本しか持たない

**⚠️ ERRORを消す目的で見出しを足さない（2026-09-09 追加）。**
出力の各行に「過半が持つ＝必須／過半に届かない＝足す根拠は弱い」が印字される。
過半に届かないトピックは、**まず読者がそれを求めている証拠を確かめる**
（①question-searchの質問に出るか ②競合の過半が持つか ③自社の同型記事が持つか）。
証拠が無ければ足さず、理由を数字つきで書く。**理由を書くのは逃げではなく判断。**

> 背景：2026-09-09「ニチレイ 気くばり御膳 口コミ」で「他社比較」（4/10サイト＝過半に届かない）のERRORを
> 消すためにH2を1本足したところ、H3 3本のうち2本が非訴求社（ナッシュ）の安さの宣伝になった。
> 実測すると question-search 25問にナッシュは0件、自社の指名×口コミ記事5本中4本が他社比較H2を持っていなかった。

**ERRORの消し方は2つだけ。①構成案に足す ②足さないなら outline.md の網羅チェック節に「入れない理由」を書く。理由を書かずに黙って落とすのは禁止。**

あわせて、競合上位の見出しを実物で `articles/{KW}/competitor-headlines.md` に保存したか確認する。集計値（字数・見出し数）だけでは網羅チェックができない。

> 背景：2026-09-08「まごころケア食 口コミ」で、上位3社すべてが扱う「8種類のコース」を良い口コミのH3 1本に埋めたまま提示した。要件定義 §6.3 に「必須トピックは抜け漏れ禁止」と書いてあったが、**数える工程が無かった**ため素通りした。

## A群-3：メインKWと共起語を競合比で採点（2026-09-09 新設・実行するだけ）

```bash
# ラッコMCP co-occurrence のレスポンスJSONを articles/{KW}/cooccurrence.json に保存してから
python3 scripts/check-kw-cooccurrence.py \
  "articles/{KW}/cooccurrence.json" "articles/{KW}/competitor.json" \
  "articles/{KW}/outline.md" "<メインKW>"
```

**ERROR 0 かつカバー率 80%以上**にする。判定の帯は実測から決めた。

| 判定 | カバー率 | 意味 |
|---|---|---|
| 合格 | 80%以上 | 媒体で最上位のページを上回る。1位を狙える |
| WARN | 60〜79% | 媒体の平均〜中央値の帯。上位は狙えるが1位は厳しい |
| ERROR | 60%未満 | 媒体平均を割る。媒体として土俵に乗っていない |

- ERRORはほかに2つ。**媒体の過半が見出しで使う語が0本かつ理由も未記載**／**メインKWの構成要素を含むH2が2本以下**（学び93）
- カバー率の上げ方は2つだけ。**①意味が良くなる形で見出しに入れる ②入れないなら outline.md の「共起語の配置計画」節に本文での置き場所か使わない理由を書く**（書けば合格に数える）
- **禁止語は分母から自動で除かれる**（コスパ・徹底・重視 等）。除外理由はスクリプトが印字するので outline に転記する
- ⚠️ **詰め込むための道具ではない。** 1見出しで満たすルールは2つまで（🚨3・結論＞平易さ＞KW）
- ⚠️ **カバー率を上げたら、提示前に3検査を通す**（auto-memory `midashi-jitsuzai-kensa`）
  - **実在検査**：見出しの名詞がサービスに実在するか。**実在しないなら動詞形にする**（「お試しセット」が存在しないのに名詞で貼った事故）
  - **入れ替え後の音読**：差し替えた**後**の文を読み直す。変更した見出しだけを抜き出して読む
  - **前提検査**：競合が持っていて自社ブランドに無い商品・機能の語は、カバー率のために貼らない

> 背景：2026-09-09「三ツ星ファーム ナッシュ 比較」でManabuさんから「ターゲットKWと共起語の使用頻度が少ない（SEO的に終わっている）」と指摘された。要件定義 §10.2 に書いてあったが**数える工程が無かった**ため素通りした。「冷凍」「宅配弁当」というカテゴリ語と「料金」「価格」が見出しに0本で、構成案は「値段」で統一していた。

## A群-4：見出しを書き換えたら記録を書く（2026-09-09 新設・**これが最優先**）

```bash
python3 scripts/check-heading-diff.py "articles/{KW}/outline.md"
python3 scripts/check-existence.py   "articles/{KW}/outline.md"
```

- `check-heading-diff.py` が**書き換えた見出しの旧→新と「消えた語」**を出す
- 変更があるのに `articles/{KW}/heading-3checks.md` に今回のハッシュが無ければ **ERROR で止まる**
- 記録を書いたら `--accept` を付けて再実行してスナップショットを更新する

**なぜ最優先か。** 2026-09-09、同じ日に**4記事**が同じ壊れ方をした。
すべてKW率・共起語カバー率という**数値目標を追って見出しを機械的に書き換えた**結果で、
「手数料」「在庫」「送料込み」「専属の」「7食から」が消え、主語がすり替わり、同義語が重複した。
3検査（実在・音読・前提）は auto-memory にもスクリプトの印字にも入れたが**止まらなかった**。

> **数値目標は機械的に上げられる。印字された文章は数値目標を止められない。**
> だから「見出しを変えたら記録を書くまで合格を出さない」形にした。

## D群：数値と法務

- [ ] **全数値を別経路で独立再計算して突合したか**（グローバル §3.2）
      → 報告値／独立再計算値／差分／ソース の表を作る。1円でも差があれば止める
- [ ] **食品は軽減税率8%**。割引は「税抜で割引 → ×1.08で税込化」の順で計算したか
      → 税込単価に割引率を掛けると数円ずれる
- [ ] **条件付きの有利な数値を無条件で出していないか**（学び74）
      → 「12食なら」「関東なら」「クーポン入力で」の条件を必ず添える
      → **自社に不利な方向の数値は条件なしで出してよい**（優良誤認にならないため）
- [ ] **自社集計の件数を優良方向の訴求に使っていないか**
      → 「口コミ20件中まずいは2件だけ」をタイトルに出すのはNG
- [ ] **通常価格の内訳が説明できない割引率を使っていないか**
      → 二重価格表示。単品合計と合わないなら「◯%OFF」も「通常◯◯円」も書かない
- [ ] **訴求社の商品への否定的評価を断定していないか**（学び59）
- [ ] **非訴求社への一方的な攻撃になっていないか**
      → 比較記事で相手が安いなら安いと書く。曲げると景表法と信頼を両方失う
- [ ] **公式で確認できない数値・仕様を見出しに置いていないか**
      → 片側しか確認できない比較項目は、見出しにも本文にも置かない

- [ ] **1点指摘されたら、同類を全件grepしてから直したか**（学び64）
      → 1つ直して再提示を繰り返さない。指摘の型を抽象化して全見出しに当てる
- [ ] **並走記事とのカニバリ回避を理由に、競合が持つトピックを削っていないか**（2026-09-08 新設）
