# 構成案の提示前チェックリスト（記憶に頼らないための1枚）

**使い方**：構成案をManabuさんに提示する**直前に必ず本ファイルを開き、全項目を1つずつ全見出しに当てる**。
lint-outline.sh が機械で見るのは A群だけ。**B群・C群は人が見るしかない**ので、記憶で済ませずここを読む。

> **なぜ作ったか**：2026-08-04、同じ型の指摘を何度も繰り返した。原因は「lintが拾わない項目を記憶で処理していた」こと。
> 覚えている範囲でやると毎回どれかが抜ける。提示前に読むファイルを1枚に固定して、記憶依存をなくす。

---

## A群：lint-outline.sh が機械検出（実行するだけ）

```bash
bash scripts/lint-outline.sh "articles/{KW}/outline.md"
```

ERROR 0 / WARN 0 になるまで直す。カバー範囲は以下。

- カッコ・記号・感嘆符・疑問符（FAQ質問H3の「〜ですか？」だけ例外）
- FAQ語尾の「？」漏れ
- AI臭ナンバリング「○つの」
- 冗長修飾（〜に関するよくある質問／〜で気をつけたい）
- 曖昧名詞（定期→定期便）
- カテゴリA硬語（試算・向き不向き・コスパ・シミュレーション・見合う 等）
- **口コミのメタ記述**（人が多い／と書く人／ほめる／に集ま 等）＝学び58
- **ネガ評価の断定**（帰属表現がないネガ語）＝学び59
- **空見出し**（〜で決まる／〜によって変わる／〜が大切）＝学び60
- **H2の金額詰め込み**（範囲表記・2つ以上の併記）＝学び61
- タイトルの年号・記号・硬語・字数

## B群：人が見る（構造・論理）

- [ ] **タイトルが疑問形なら、H2①がその疑問への回答になっているか**（学び70）
      → 事実の羅列から入らない。1059「オイシックスが高いのは〜だから」の型
- [ ] **H1とH2①が同じことを言っていないか**（§8-12 三重掲載）
      → タイトル＝問い＋何が分かるか／H2①＝答え、で役割を分ける
- [ ] **H2とH3が同じ話を繰り返していないか**（🚨12）
- [ ] **各H2の約束に、配下H3が全部答えているか**（§9）
      → H2の結論がH3を束ねられる広さか。狭すぎるとH3が浮く
- [ ] **中身が2つしかないものをH2にしていないか**（🚨21・学び68）
      → H3が2本なら本文1文に落とすか、隣のH2に統合する
- [ ] **唐突な見出しがないか**（🚨10）
      → 前のH2から話が飛ぶなら、見出しか導入文で橋渡しする
- [ ] **何のセクションか目次で分かるか**
      → H2が主張文だけだと役割が読めない。不満なら不満、対処なら対処と分かる形に
- [ ] **行動を促すセクションの見出しが終止形になっていないか**（学び75）
      → 「配送回数を減らす」→「減らそう」
- [ ] **並走記事・既存公開記事とH3単位で突合したか**（学び73）
      → H2だけ見ると見逃す。必ずH3を並べる

## C群：人が見る（日本語・読みやすさ）※ここが一番抜ける

- [ ] **1つの見出しに主語（ブランド名）を2つ以上入れていないか**（学び76）
      → 比較記事でも、H1で2社が確定していれば以降は省ける
- [ ] **ブランド名が全H2に入っていないか**（学び57系）
      → 目安は**H2の半分以下**。1本目・FAQ・まとめに置けば文脈は続く
- [ ] **見出しに数字を詰め込んでいないか**
      → H2の金額はA群が見る。**H3も数字の羅列にしない**。1見出しに数値は1〜2個まで
- [ ] **1見出しで満たすルールは2つまでか**（学び62）
      → 結論＋実額＋KWを1本に詰めない。優先順は 結論 > 平易さ > KW
- [ ] **中学生が一読で像が浮かぶか**
      → 意味不明語の実例：好みのカスタム／副菜の出来／おかずの質／口に合わないときの食べ方
- [ ] **同じ語尾が3連続していないか**（writing-manual §1 段落の語尾）
- [ ] **見出しが長すぎないか**
      → 実記事のH2は26〜31字。**32字を超えたら詰め込みを疑う**
- [ ] **H2だけを上から読んで記事の筋が通るか**
- [ ] **声に出して読んだか**（音読チェック・SKILL.md Phase 5）
      → 数字と助詞のつながりが会話として成立するか

## D群：数値と法務

- [ ] **全数値を別経路で独立再計算して突合したか**（グローバル §3.2）
      → 報告値／独立再計算値／差分／ソース の表を作る。1円でも差があれば止める
- [ ] **食品は軽減税率8%**。割引は「税抜で割引 → ×1.08で税込化」の順で計算したか
      → 税込単価に割引率を掛けると数円ずれる
- [ ] **条件付きの有利な数値を無条件で出していないか**（学び74）
      → 「12食なら」「関東なら」「クーポン入力で」の条件を必ず添える
      → **自社に不利な方向の数値は条件なしで出してよい**（優良誤認にならないため）
- [ ] **自社集計の件数を優良方向の訴求に使っていないか**
      → 「口コミ20件中まずいは2件だけ」をタイトルに出すのはNG
- [ ] **通常価格の内訳が説明できない割引率を使っていないか**
      → 二重価格表示。単品合計と合わないなら「◯%OFF」も「通常◯◯円」も書かない
- [ ] **訴求社の商品への否定的評価を断定していないか**（学び59）
- [ ] **非訴求社への一方的な攻撃になっていないか**
      → 比較記事で相手が安いなら安いと書く。曲げると景表法と信頼を両方失う
- [ ] **公式で確認できない数値・仕様を見出しに置いていないか**
      → 片側しか確認できない比較項目は、見出しにも本文にも置かない

- [ ] **Codexレビューを3観点で回したか**（①1位が取れるか ②日本語 ③景表法・信用毀損）
      → **回さずに提示しない**。2026-08-04、これを飛ばした記事で冗長さの指摘が再発した
- [ ] **1点指摘されたら、同類を全件grepしてから直したか**（学び64）
      → 1つ直して再提示を繰り返さない。指摘の型を抽象化して全見出しに当てる
- [ ] **H2だけ先に提示して合意を取ったか**（学び63）
