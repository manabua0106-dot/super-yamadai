**正本**：`rules/writing-manual.md`

## このファイルの役割

Manabuさんからの**新しい構成に関する指摘**を日付付きで一時記録する場所です。

### 運用フロー

```
1. 新しい指摘を受ける
   ↓
2. このファイルに日付付きで追記
   ↓
3. 同じ指摘が3回以上 or 恒久ルール化が妥当と判断
   ↓
4. writing-manual.md に昇格
   ↓
5. このファイルから該当項目を削除（SSOT 維持のため二重管理回避）
```

### 記録フォーマット

```markdown
## YYYY-MM-DD: 指摘のタイトル

### 学びN: 簡潔なルール名

- NG: 具体的な NG 例
- OK: 具体的な OK 例
- **ルール**: ルールの要約
- **適用範囲**: 全記事 / 特定セクション / 特定記事タイプ
- **昇格候補**: writing-manual.md の該当セクション
```

> **横展開ルーチン（2026-07-02 新設）**：学びを追記するとき「これは3PJT（ヤマダイ／コムラッド／MARKETING PICKS）共通の学びか、ヤマダイ固有か」を判定し、共通なら学びの末尾に `横展開：要（対象PJT）` を1行付ける。「要」の学びは、次にそのPJTで作業するときに該当ルールファイル（kosei-sakusei要件定義・iron-rule・outline-design等）へ反映する。

#### 学び71: 公式サイト内で数字が食い違うときの新旧判定手順

- 事例: DELIPICKSのお弁当単価が公式トップ「税抜920円/税込994円」・ヘルプ「税抜880円/税込950円」で食い違った
- **判定手順**（この順で見る）: (1)**割引後価格まで整合しているか**（トップは10/15/20%OFF後の894/845/795円まで920円基準で整合） (2)**価格改定の時期を調べる**（2026年7月13日に改定と判明） (3)**同じ記事内の他の数値が一致するか**（ヘルプのご飯290/313はトップと一致＝お弁当だけ更新漏れ） (4)競合記事の数値は改定前で止まっていることが多く判定に使える
- **ルール**: 公式内で不一致があったら「新しい方」を推測で決めない。上記4点で根拠を作ってから確定し、outline に判定根拠を残す

#### 学び72: 「通常価格」が単品合計と合わないときは割引率を使わない

- 事例: お試しセット公式表記「通常5食+ごはん1食 ¥6,380（税込¥6,910）→ 53%OFF」。単品合計は税抜920×5＋290＝**4,890円**で**1,490円合わない**。内訳の説明も商品ごとの単価差の記載も公式にない
- **ルール**: 二重価格表示（有利誤認）のリスクがあるため、**通常価格の内訳が説明できないときは「通常◯◯円」「◯%OFF」を見出しにも本文にも書かない**。書けるのは実売価格と条件（税込3,218円・送料無料・初回1回限り・定期便に移行しない）だけ。付録1 #5「初回半額 → 初回限定の割引キャンペーンあり」と同じ扱い

#### 学び73: 並走記事のカニバリはH3単位で突き合わせる

- 事例: 「まずい」と「値段」でH2見出しは別物に見えたが、**H3を並べたら4本とも同一データ**（実額・まとめ買い割引・自炊外食比較・最低注文金額）だった
- **ルール**: 並走記事があるときは**H2ではなくH3で突合**する。H2だけ見ると見逃す

#### 学び74: 自社に有利な条件付きの数値は、条件とセットでしか出さない（2記事連続で発生）

- 事例1（まずい）: 「口コミ20件中まずいは2件だけ」を無条件でタイトルに → 自社が集めた極小サンプルを優良方向に使う景表法リスク
- 事例2（値段）: 「送料込み1食935円」を無条件でタイトルに → 実際は「関東・12食・15%引き後」の条件付き。6食なら1,175円
- **ルール**: 有利な数値をタイトル・見出しに出すときは**条件を必ず併記**するか、出さない。「12食なら送料込み1食935円」の形にする。**逆に自社に不利な方向の数値（不満は値段のほうが多い等）は条件なしで出してよい**（優良誤認にならないため）
- **2記事連続で同じ型を出した**ので、提示前に「この数字は無条件で成り立つか」を必ず1回問う

#### 学び75: 行動を促すセクションの見出しは終止形にしない

- NG: 「デリピックスを安く頼むならまとめ買いで配送回数を**減らす**」

- **ルール**: 読者の行動に落とすセクション（安く使う頼み方・まとめ等）の見出しは「〜しよう」で締める（§E-1で「〜しましょう」は使用可）。事実提示のH2は終止形のままでよい

#### 学び77: 廃止したルールファイルを `_archive/` に移しても自動ロードは止まらない（最優先・再発すると全ルールが無効化する）

- 事象: `writing-manual.md` を v5.0（250行・製本方式）に作り直し、旧v4.1（1,787行）を `.claude/rules/_archive/writing-manual-v4.1.md` に退避したが、**`.claude/rules/` 配下の `.md` は再帰的に自動ロードされる**ため、旧版が毎セッション注入され続けていた
- 悪いことに旧版の冒頭は「**このファイルが Single Source of Truth（唯一の正本）です。CLAUDE.mdと矛盾した場合はこのマニュアルが優先されます**」と自称しており、しかも**新版の7倍の分量**。新セッションのClaudeは矛盾する2つの正本を読むことになる
- 旧版には、実測で「上位記事で使われていない」と確認して**廃止したPASONA法・FAB法**がそのまま残っていた
- **ルール**: ルールファイルを廃止するときは、`_archive/` に移すだけでなく**拡張子を `.md` 以外にする**（`.md.archive`）。移動先のフォルダ名では自動ロードは止まらない
- **状態**: ✅ 2026-08-05 `writing-manual-v4.1.md` → `writing-manual-v4.1.md.archive`（113,841バイト無傷）。CLAUDE.md・writing-manual.md の参照パスも更新

#### 学び78: Ahrefs `keywords-explorer-overview` の keywords は**カンマ区切り**。改行区切りは空配列を返す

- 事象: 「デリピックス お試し」の検索数を取ろうとして改行区切りで5KWを渡し、`{"keywords": []}` が返った。これを**「Ahrefsの検出閾値以下＝データなし」と断定して報告**した。実際はカンマ区切りで渡し直すと **検索数250・CPC80円**で存在していた
- 加えて `serp-overview` が空を返したことも「データなし」の根拠に使ったが、既知の大きいKW（ナッシュ お試し）で試すと12行返るため**ツールは正常**で、低ボリュームKWにSERPスナップショットが無いだけだった
- **ルール**: (1) keywords は**カンマ区切り**で渡す (2) **空配列が返っても「データなし」と断定しない**。既知の大きいKWで同じ呼び出しを試し、ツールの正常性を切り分けてから結論を出す（グローバル §3.2.1「無い・失敗した」は根拠の実出力とセット）
