## このファイルの役割

Manabuさんからの**新しい文体に関する指摘**を日付付きで一時記録する場所です。

### 運用フロー

```
1. 新しい指摘を受ける
   ↓
2. このファイルに日付付きで追記
   ↓
3. 同じ指摘が3回以上 or 恒久ルール化が妥当と判断
   ↓
4. writing-manual.md に昇格
   ↓
5. このファイルから該当項目を削除（SSOT 維持のため二重管理回避）
```

### 記録フォーマット

```markdown
## YYYY-MM-DD: 指摘のタイトル

### 学びN: 簡潔なルール名

- NG: 具体的な NG 例
- OK: 具体的な OK 例
- **ルール**: ルールの要約
- **適用範囲**: 全記事 / 特定セクション / 特定記事タイプ
- **昇格候補**: writing-manual.md の該当セクション
```

## 現在の蓄積

### 2026-05-16: 宅配弁当二人暮らし記事の指摘

#### 学び1: 「実質単価」「実質〇〇円」は読者に伝わらない

- NG: 「想定より高い実質単価で続けることになります」「送料込みの実質単価で計算すると」「実質799円」
- OK: 「想定より高い料金で続けることになります」「送料込みの1食あたり料金で計算すると」「送料込み1食799円」
- **ルール**: 「実質単価」「実質〇〇円」は業界用語的でわかりづらいため完全禁止。「送料込みの1食あたり料金」「送料込み〇〇円」に統一する
- **適用範囲**: 全記事
- **昇格先**: ✅ writing-manual.md 付録2 カテゴリA / prohibited-words.md カテゴリA

#### 学び2: pタグは絶対に出さない

- NG: `<p>導入文…</p>` で囲む
- OK: H2/H3直下の導入文も「。」の直後に空行を入れる一文一改行で表現
- **ルール**: pタグは記事内に1つも入れない。WordPress側で自動付与されるため二重になる
- **適用範囲**: 全記事
- **昇格先**: ✅ writing-manual.md §D-1補足（新設）

#### 学び3: 本文の具体例とulを二重に書かない

- NG: 「平日夕食だけなら週10食、共働きで朝晩取り入れるなら週14食程度が目安になります」→ 直後にul（同内容を箇条書きで再掲）→ strong締め
- OK: P（結論）→ R（理由）→ ul（具体例を箇条書き）→ strong締めで本文の具体例文は省略、または ul の上はul全体の導入1文のみ
- **ルール**: 本文の具体例文と直後のulが同じ情報を述べていたら、本文側を削除して ul に集約する。strong締めはul全体の要約・行動・目安として機能させる
- **適用範囲**: 選び方・メリット・注意点の全H3
- **昇格先**: ✅ writing-manual.md §E-2補足（PREP法）・§G-4（セクション完了チェックリスト）

#### 学び4: 「〜が基本です」「〜と覚えておきましょう」のような冗長な断言NG

- NG: 「宅配弁当の料金を比較するときは、送料込みの1食あたり料金で見るのが基本です」
- OK: 「宅配弁当の料金は、送料込みの1食あたり料金を確認しましょう」
- **ルール**: 「〜が基本です」「〜と覚えておきましょう」「〜が大切です」など、断言＋自明な締めは削除して簡潔にする
- **適用範囲**: 全記事
- **昇格先**: ✅ writing-manual.md 付録2 レイヤー4

#### 学び5: 「〜しやすくなります」「〜やすくなります」の冗長表現

- NG: 「サービス間の比較がしやすくなります」
- OK: 「サービス間の比較がしやすいです」
- **ルール**: 「〜なります」を付けて冗長にしない。「〜です」「〜できます」で言い切る
- **適用範囲**: 全記事（特にstrong締め）
- **昇格先**: ✅ writing-manual.md §E-2補足（strong締めのバリエーション）

#### 学び6: 「圧迫」は日常会話に言い換える

- NG: 「冷凍庫を圧迫し」「冷凍庫を圧迫する」「圧迫感」
- OK: 「冷凍庫のスペースを多く使う」「冷凍庫がぎゅうぎゅうになる」「冷凍庫のスペースをたくさん取る」
- **ルール**: 「圧迫」は硬い漢語的でわかりづらい。日常会話的な言い換えを使う
- **適用範囲**: 全記事
- **昇格先**: ✅ writing-manual.md 付録2 カテゴリA / prohibited-words.md カテゴリA

#### 学び7: ul/ol内の li に「。」を入れない（中段でも）

- NG: `<li>冷凍タイプ:Dr.つるかめキッチン・nosh・Mealsなど。在宅時間が不規則な夫婦向け</li>`
- OK: `<li>冷凍タイプ(在宅時間が不規則な夫婦向け):Dr.つるかめキッチン・nosh・Mealsなど</li>`
- **ルール**: li 内には句点（。）を一切入れない（項目末・中段ともに）。「。」を使うほど長くなる場合はtableに変換する
- **適用範囲**: 全記事
- **昇格先**: ✅ writing-manual.md §D-3 リストタグ

#### 学び8: 表の各セルが長すぎる場合は列を分割する

- NG: 1列のtdに「送料990円+本体7,000円=合計7,990円(送料込み1食799円)」のように複数情報を詰め込む
- OK: 「本体料金」「送料」「合計」「1食料金」と列を分けて、各セルは単一の値のみ
- **ルール**: tdが20文字を超える場合は列分割を検討する。本文用tableは情報項目ごとに列を分ける（サービス紹介テーブルとは別ルール）
- **適用範囲**: 本文中のtable全般
- **昇格先**: ✅ writing-manual.md §D-4 テーブルタグ

#### 学び9: 「タイプ別の特徴」「観点別の比較」など抽象的な見出しNG

- NG: 「タイプ別の特徴と二人暮らしでの向きをまとめます」「観点別に比較します」
- OK: 「冷凍タイプと冷蔵タイプの代表サービスを以下にまとめます」（何の話か具体名で書く）
- **ルール**: 「タイプ別」「観点別」「ポイント別」等の抽象語は禁止。何を比較・整理するのか具体名（冷凍/冷蔵・サービス名・項目名）で書く
- **適用範囲**: 全記事のul/table導入文
- **昇格先**: ✅ writing-manual.md 付録2 カテゴリC（AI構文パターン）

#### 学び10: 登録済みサービスは画像＋テーブルを `_table` ショートコードで置換

- NG: 登録済みサービスのH3直下に `<img>` ＋ `<table>` を直書き
- OK: H3直下に `[サービス名_table]` のみ1行配置（画像＋テーブルを一括展開）
- **ルール**: Post Snippets に `_table` 登録済みのサービス（11ブランド）は必ずショートコードに置換する。未登録のサービスのみ画像＋テーブル直書き
- **登録済み11ブランド**: Oisix / コープデリ / ヨシケイ / ラディッシュボーヤ / Dr.ツルガメキッチン / Meals / タイヘイ / ワタミ / 筋肉食堂DELI / watamidirect / lifemeal
- **注意**: lifemeal は「ライフミール」用で、まごころケア食とは別ブランド（同じシルバーライフ運営だがターゲット世代が異なる）
- **適用範囲**: 全記事のサービス紹介H3
- **昇格先**: ✅ writing-manual.md §C-1補足2 / shortcodes.md
