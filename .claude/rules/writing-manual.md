## 0. 執筆ワークフロー

### 0-1. KW選定・検索意図の把握
1. メインKW（「食材宅配 一人暮らし」等）を決定する。
2. サジェスト・PAA（People Also Ask）・再検索KWを取得し、読者が知りたい情報を一覧化する。
3. 検索意図を「比較検討」「知識獲得」「購入直前」のどれかに分類し、記事の方向性を決める。

### 0-2. 競合リサーチ
1. メインKWで検索し、上位5〜10記事のH2/H3構成・掲載サービス数・独自コンテンツを表に整理する。
2. 上位記事が共通して扱っている要素を「必須要素」としてリスト化する。自社記事に抜け漏れがあってはならない。
3. 上位記事が扱っていない、または弱い要素を「差別化余地」としてリスト化する。
4. 差別化は「H3を無駄に増やす」のではなく、「既存H3の情報密度・具体性で上回る」方向で行う。読者のニーズから外れる冗長な追加はしない。
5. 上位記事の中で評価できる構成や表現はTTP（徹底的にパクる）し、自社記事に取り込む。

### 0-3. 構成案の作成
1. A-1の標準セクション構成に従い、H2/H3の見出しを仮決めする。
2. H3の見出しは以下の優先順位で決める：
   (a) 検索意図・サジェストから導かれる読者ニーズ
   (b) 競合の必須要素（上位5記事中3記事以上が扱っている項目）
   (c) 差別化要素（競合にない独自の切り口）
3. 掲載サービスの選定：訴求社を優先し、非訴求社はSEO網羅性のために追加する。
4. FAQのネタ出し：サジェスト・知恵袋・PAA・競合のFAQを確認し、本文で扱っていないニーズに限定する。

### 0-4. 執筆
推奨する執筆順序：
1. サービス紹介（テーブル → 紹介文 → CTA）
2. 選び方
3. メリット
4. 注意点
5. FAQ
6. 導入文（本文完成後に書いた方が内容と齟齬が出ない）
7. まとめ

【v3.0追加】執筆時の出力ルール：
・改善後のHTMLは必ずコードブロック（```html）で出力する。
・修正箇所を提示する際は、変更前→変更後を明示する。

### 0-5. セルフチェック → 納品
1. セクション単位で品質チェック（G-3のチェックリスト）を行う。
2. 全文完成後に通しで読み、セクション間の重複・トーンの統一を確認する。
3. 競合比較チェック：上位3記事と構成を比較し、必須要素の抜け漏れがないか、情報が薄いH3がないか確認する。
【v3.0追加】4. 表現の出現回数チェックは推測でなく必ず検索（Ctrl+F）して正確にカウントする。

## A. 記事全体の構造

### A-1. 標準セクション構成

| # | セクション | 内容・ルール |
|---|-----------|------------|
| 1 | 導入文（H2なし） | 読者の悩み提起 → 記事の内容紹介 → strongタグの太字アクション促し文。H2は立てず本文のみ。 |
| 2 | 選び方（H2） | H2直下に導入1〜2文 + olリストで項目一覧 → H3×4〜5本で各ポイント解説。 |
| 3 | サービス紹介（H2） | H2直下に導入文 + olリストで全社名一覧 → H3×各社（テーブル＋紹介文＋CTA）。 |
| 4 | メリット（H2） | H2直下に導入1〜2文 + olリスト → H3×3〜4本。各H3末尾に太字締め文。 |
| 5 | 注意点（H2） | H2直下に導入1〜2文 + olリスト → H3×3〜4本。各H3末尾に太字締め文。 |
| 6 | FAQ（H2）※任意 | H2直下に導入文 → H3×3〜4本。本文で扱っていないユーザーニーズに限定。本文の焼き直しは禁止。 |
| 7 | まとめ（H2） | strongタグの要約文 + 行動促し。短く締める。画像がある記事もある。 |

※ 記事テーマにより「料金相場」セクション（テーブル＋解説文、H3なし）や「〜とは？」セクションが追加される場合がある。

### A-2. 導入文のルール
1. 【v3.0変更】1文目にメインKWを必ず含める。「〜は、＜読者メリット＞の食材宅配サービスです。」の型で始める。
2. 読者の悩みを「〜ですよね。」「〜大変ですよね。」で共感する。
3. 記事の内容を「〜紹介します」「〜解説します」で予告する。
4. 末尾にstrongタグで囲んだ行動促しの一文を入れる。
5. 導入文にH2は立てない。
6. 【v3.0追加】導入文で書いた内容を直後のH2セクションで繰り返さない。導入文は簡易表現に留め、詳細はH2セクションに集約する。

### A-3. セクション導入パターン
各H2セクションの冒頭は以下の型に従う：
(a) 導入文2〜3文（セクション全体の要約）
(b) olタグの番号付きリストで、直下のH3項目を一覧化（FAQ・まとめ除く）
(c) 各H3で個別解説
※ olリストの各li要素とH3見出しのテキストは完全一致させる。
【v3.0追加】※ H2直下の導入文は、単なる宣言（「〜を紹介します」）ではなく、読者にとってのリスクや必要性を述べる。

NGパターン → 対処法：
・「10社のミールキットを紹介します」（宣言だけ） → 「ミールキットは各社で料金・配送エリア・メニュー内容が大きく異なります。比較せずに申し込むと割高なサービスを選んでしまう可能性があります。」（リスクを述べる）
・セクション導入文・まとめ文が記事間でほぼ同一 → テーマ固有の悩みや状況に触れる一文を必ず入れて差別化する

## B. サービス紹介セクションの書き方

### B-1. テーブル仕様
各サービスのH3直下に、以下5項目のテーブルを必ず配置する。項目数は5行で固定。

| 項目（th） | 内容・ルール |
|-----------|------------|
| 会社 | 正式な運営会社名 |
| 費用 | お試し価格・定期価格・送料情報。税込表記を統一。記事テーマに関連する価格を優先記載。 |
| 配送エリア | 全国 / 地域限定（具体的な都道府県名を列挙）。除外条件も必ず併記。 |
| 配送日時の設定 | 指定可否、頻度、置き配対応の有無。 |
| お試しの有無 / お試し内容 | 総合比較記事→「お試しの有無」、お試し特化記事→「お試し内容」。記事テーマに応じてth名を使い分ける。 |

### B-2. 紹介文の構成
テーブル直下に3〜5段落の紹介本文を書く。以下の構成を基本とする。

- 段落1: サービスの一言要約（strongタグで太字化）。「〜は、＜特徴＞の食材宅配サービスです。」の型。strong 1文目には記事テーマのメインKWまたは「冷凍宅配弁当」等の複合KWを自然に含める。
  【v3.0追加】※ 段落1の特徴は1つに絞る。複数の情報を入れる場合は2文に分割する。1文に詰め込まない。
- 段落2〜3: 具体的な特徴・強み（料金、品質、メニュー内容、利便性等）。
  【v3.0追加】※ テーブルに記載した情報を本文で同じ角度・同じ数字で繰り返さない。本文ではテーブルにない読者メリットや使い方の情報を書く。
- 段落4:【v3.0変更】訴求社の場合：お試し情報やキャンペーン（strongタグで価格を太字化）。CTA直前の価格訴求文として必ず配置する。非訴求社の場合：strong価格訴求文は不要。簡潔なキャンペーン情報のみ記載する。
- 段落5（任意）: まとめの一文。

NGパターン → 対処法：
・紹介文の構成・順序・表現が別記事とほぼ同一 → 段落の順番を入れ替え、書き出しを変える。記事テーマに合わせた切り口で書き直す
・「厳選した食材を全国に届ける食材宅配サービスです」等の汎用フレーズ → 記事テーマの切り口を冒頭に入れる
・テーブルのtd内容が全記事でコピペ同一 → 費用欄はその記事テーマに関連する価格情報を優先的に記載する
・サービス紹介の冒頭が全社「○○は、〜の食材宅配サービスです。」で始まる → 書き出しのパターンを最低3種類用意する
・サービス紹介文が機能の羅列だけで、読者のメリットに変換されていない → 「カット済み食材で届く」→「包丁を使わずに10分で夕食が完成します」のように変換する
・「お得に始められます」だけで、何と比較してお得なのか不明 → 「通常価格○○円のところ、お試しセットなら△△円で試せます」と具体的な比較を入れる

### B-2補足. 記事テーマ別の紹介文の切り口

| 記事テーマ | 段落1の切り口例 | 強調ポイント |
|-----------|---------------|------------|
| 総合比較 | 「〜は、＜代表的な特徴＞の食材宅配サービスです。」 | サービス全体の特徴をバランスよく |
| お試しセット | 「〜のお試しセットは、＜価格・割引率＞で体験できる〜」 | お試し価格・内容・割引率・返金保証 |
| 離乳食 | 「〜の＜離乳食シリーズ名＞は、＜月齢対応＞の〜」 | 月齢対応・安全性・アレルギー配慮 |
| 安さ特化 | 「〜は、＜価格の安さ＞が魅力の食材宅配サービスです。」 | 1食あたり単価・送料無料条件 |
| 一人暮らし | 「〜は、＜一人暮らし向けの利点＞の食材宅配サービスです。」 | 少量注文・冷凍保存・配送柔軟性 |

## D. HTML / WordPress記法

### D-1. 見出しタグ
H2: セクションの大見出し。H3: セクション内の小見出し。サービス紹介では「1.サービス名」の形式で通し番号を付ける。
H4以下は原則使わない。
※ コピペ時にH2タグが重複しないよう注意する。納品前に全H2タグの数を数えて確認する。

### D-2. 画像タグ
【v3.0変更】各H2セクションの直下（導入文の前）にimgタグを配置する。
H3直下の画像はサービス紹介セクションのH3のみ。選び方・メリット・注意点・目的別のH3には画像を入れない。

構文：
<img class="size-full wp-image-XXX aligncenter" src="https://www.super-yamadai.co.jp/article/wp-content/uploads/YYYY/MM/filename.jpg" alt="" width="800" height="XXX" />

・class: 「size-full wp-image-XXX aligncenter」
・alt: 空文字（alt=""）で統一。
・width: 800で固定。

### D-3. リストタグ
セクション冒頭の項目一覧: olタグ（番号付きリスト）+ liタグ。
【v3.0変更】本文中の箇条書き: 原則使用しない。ただし3つ以上の項目を並列で比較する場面ではul+liを使用してよい。
【v3.0追加】※ ul/li内の項目末には句点（。）を入れない。

### D-4. テーブルタグ
・tableにstyle="width: 100%;"を指定。
・左カラム: th（項目名）、右カラム: td（内容）。
・thのwidth: 25.8158%、tdのwidth: 74.1117%。
・行数は5行で固定（B-1参照）。

### D-5. strongタグ
使用場面は以下の5パターンに限定する。それ以外では使わない。
(a) 選び方・メリット・注意点セクションの各H3末尾の要約・アクション促し文（1文まるごと太字）
(b) サービス紹介文の段落1の特徴キャッチ部分
(c) 【v3.0変更】訴求社のサービス紹介文のCTA直前の価格訴求文（段落4）。非訴求社には使用しない。
(d) 価格・割引情報の強調
(e) 導入文の末尾アクション促し文
※ 1段落にstrongが2箇所以上にならないようにする。

### D-5補足. サービス紹介文のstrong締め（価格訴求文）
【v3.0変更】訴求社のサービス紹介文の最終段落（CTA直前）に、価格・割引情報をstrongタグで太字化した1文を配置する。非訴求社にはstrong価格訴求文を入れない。

OK例：
<strong>定期コースなら全コース28%OFF・送料無料で、最安のバランス栄養御膳は1食あたり約710円（税込）</strong>から始められます。
<strong>初回お試しセット（5食＋ごはん1食）が通常価格から47%OFFの3,218円（税込）</strong>で注文できます。

NG例：
・strong締めがなく、紹介本文の後すぐにCTAボタンが来る（訴求社の場合）
・strongの中に価格情報がなく「おすすめです」「向いています」等の感想で終わる

【v3.0追加】※ strong締め文の直後に注記がある場合は、strongの外に※で分離する。

### D-6. フォーマット整合性の注意点
NGパターン → 対処法：
・H2直下にH3が1本しかないのにH3を立てている → H3が1本のみの場合はH3を立てず、H2直下にテーブルと本文を直接置く
・olリストの項目テキストとH3見出しテキストが不一致 → olリストの各li要素とH3見出しのテキストを完全一致させる
・サービス紹介テーブルの項目が4行や6行になっている → 必ず5行で統一する
・まとめのH2見出しに「：」と「｜」が混在 → 記事内で記号は統一する。「：」で統一
・CTAボタンの直前にキャッチコピー行がある社とない社が混在 → 訴求社は全社統一する
・H2タグが重複している → コピペ時の貼り付けミスに注意。納品前に全H2タグの数を確認する
・Post Snippetsのショートコードが別サービスのリンクに紐づいている → 使用前にPost Snippets管理画面でリンク先URLを確認する

## E. 文章作法

### E-1. 文体・トーン
敬体（です・ます調）で統一する。読者に語りかける口調を基本とし、「〜ですよね」「〜してみてください」を適度に使う。
過度にフランクにはせず、「信頼できる情報メディア」のトーンを維持する。

### E-2. H3セクションの末尾パターン
選び方・メリット・注意点セクションのH3では、最終段落をstrongタグの太字一文で締める。
太字一文は「具体的な行動」または「読者にとっての価値」を述べる。抽象的な感想で終わらない。
1文目（PREP結論）とstrong締めが同じ内容にならないようにする。1文目は「何ができるか」、strongは「読者にとっての価値」や「具体的な行動」で角度を変える。

OK：「公式サイトで郵便番号を入力すれば対象エリアかどうか調べられます。」
OK：「買い物にかかっていた時間を、自分の休息や趣味に使えるようになります。」
NG：「美味しさだけでなく、健康面でも安心できるのが大きな魅力です。」（感想止まり）
NG：「生活にゆとりが生まれます。」（抽象的）
NG：1文目「電子レンジで温めるだけで主菜・副菜がそろった食事がとれます」→ strong「電子レンジで温めるだけで栄養バランスの整った食事がとれます」（ほぼ同一）→ 角度を変える

※ サービス紹介セクションのH3にはこのパターンではなく、D-5補足の価格訴求文で締める（訴求社のみ）。

### E-2補足. H3冒頭は結論から
選び方・メリット・注意点セクションの各H3は、結論または要点から始める。背景説明から入らない。

NGパターン → 対処法：
・「食材宅配サービスは、会社ごとに特徴が大きく異なります。」（説明から開始） → 「お試しセットをいくつか試してみると、自分のニーズに合ったサービスを見つけやすくなります。」（結論から開始）
・「赤ちゃんの成長に欠かせない栄養を〜」（背景から開始） → 「管理栄養士が監修したメニューなら、月齢に応じた栄養を手軽に摂れます。」（結論から開始）

各H3の本文は見出しのテーマに限定する。見出しと無関係な情報が混入している場合は削除するか、適切なH3に移動する。

### E-3. 一文一情報・文長の目安
1文に複数の情報を詰め込まない。1文は30文字以内を目安とし、最長でも80文字を超えないようにする。
【v3.0追加】文末の。の後は必ず改行する。同じ段落内で2文以上を続けない（ただしul/li内は除く）。

### E-4. 体言止めの禁止
本文中の体言止め（「〜を実施。」「〜に対応。」）は使用しない。必ず「〜しています。」「〜です。」「〜できます。」で締める。

### E-5. 同じ表現の繰り返し回避
記事全体で同じ締め方や同じフレーズが3回以上出現しないようにする。執筆後にCtrl+Fで検索して確認する。
【v3.0追加】連続する3文以上が同じ語尾（〜ます。〜ます。〜ます。）にならないようにする。

NGパターン → 対処法：
・「〜で安心して利用できます」が5社連続で出現 → 「気軽に始められます」「不安なく利用できます」等バリエーションを出す
・「〜が特徴です」が近い位置で3回以上 → 「〜に定評があります」「〜が魅力です」等に分散する
・「忙しい方にもおすすめです」が記事内で3回以上 → 3回以上使っている表現を洗い出して言い換える
・サービス紹介の冒頭が全社同じ型 → 書き出しのパターンを最低3種類用意する
・H3末尾の太字文が全セクション「〜してみてください。」で統一 → 「〜と安心です。」「〜と失敗しにくくなります。」等のバリエーションを混ぜる

### E-6. 比喩表現の禁止
物理的な意味と混同しうる比喩表現は使用しない。直接的な表現に置き換える。
NG：「コストが跳ね上がる」→ OK：「費用が高くなる」
NG：「食費がふくらむ」→ OK：「食費が予算を超えやすい」

### E-7. 内部リンク誘導文の禁止
「○○について詳しく知りたい方は『□□□□□□』も参考にしてみてください」等の内部リンク誘導文は使用しない。テーブル内のジャンプリンクのみ許可。

### E-8. 禁止語・制限語
完全禁止：
・「こと」（名詞化の「〜できること」等）→ 動詞で書き直す
・「として」→ 具体的な表現に書き直す
・「という」→ 直接記述する
・「といった」→ 「〜や〜など」に置き換える
・指示語（「これ」「その」「この」「そうした」）→ 具体的な名詞で書き直す。ただし「この記事では」はOK
【v3.0追加】※「そのまま」は副詞的用法のため指示語禁止の対象外。

制限あり：
・「〜い。」で終わるアドバイス文 → 「〜です。」「〜できます。」「〜してください。」で締める
・「」（カギ括弧）→ 会話文・固有名詞・読者の心理描写のみに使用する。強調目的では使わない

### E-9. 読者視点の担保
【v3.0追加】すべての記述が「読者にとって何の役に立つか」を意識する。
・業界用語をそのまま使わない。初出時に平易な言葉で補足する（例：「独自の安全基準『RADIX基準』（農薬・添加物の使用制限ルール）」）。
・業界の正式名称にこだわらず、読者に伝わる言葉を優先する（例：「出資金」→「預け金」）。
・サービス紹介文が機能の羅列だけにならないようにする。「カット済み食材で届く」→「包丁を使わずに10分で夕食が完成します」のように読者の生活での効果に変換する。
・「〜を確認しましょう」だけで終わらない。具体的な方法を添える。
・「お得に始められます」だけで終わらない。何と比較してお得なのかを明示する。
・strong締めは直前の本文から自然に導ける内容にする。本文で述べていない論理に飛ばない。
・主語が省略されて何の話か分からない文を避ける。

### E-10. つながりのある段落構成
2文を並べただけの段落を避ける。前の文と次の文が論理的につながっているか確認する。

NG：「全国配送に対応しています。配送日時の指定も可能です。」（関連が弱い）
OK：「全国配送に対応しており、配送日時も指定できるため、ライフスタイルに合わせて利用しやすいサービスです。」

## G. 品質管理チェックリスト

### G-1. 事実確認
すべての記述は公式サイトで事実確認できるものに限る。確認できない情報は書かない。
【v3.0追加】出典を記載する場合は、URL単位で裏取りできるデータのみ使用する。加工・推計した数字を出典付きで書かない。
景表法・薬機法・健康増進法に抵触する表現がないか確認する。

NGパターン → 対処法：
・公式サイトで確認できない数字を断言する → 裏取りできる数字のみ記載する
・「No.1」「業界最安値」等を根拠なく使う → 調査機関名・調査年・調査条件を明記できる場合のみ
・「コスパの良さ」「最安クラス」等の比較表現を根拠なく使う → 景表法リスク。具体的な価格に置き換える
・「一流シェフ」「手作り」「本格的」等の品質を断言する → 景表法リスク。事実ベースの表現に変更
・特定栄養素の不足・効果を断言する → 健康増進法リスク。一般的な表現に留める
・割引表現で比較対象が不明 → 比較対象を明示する
・「送料無料」と書くが条件を省略する → 条件を必ず併記する
・お試し価格が古い情報のまま → 執筆時点で公式サイトの価格を確認する
・配送エリアの都道府県名が不正確 → 具体的な都道府県名を列挙する
・「全国対応」で除外条件を省略する → 「全国（一部離島を除く）」等で併記
・疾患名＋対象者表現の組み合わせ → 薬機法リスク。一般的表現に留める

### G-2. 記事間の重複防止
同じサービスが複数記事に登場する場合、紹介文の構成・表現を記事ごとに変える。3文以上同一の箇所がないかチェック。

### G-3. 記事内のセクション間重複防止
選び方・メリット・注意点・FAQ・目的別の各セクションで、同じ内容を同じ角度で書かないようにする。

NGパターン → 対処法：
・選び方H3とメリットH3で同じテーマを同じ角度で扱っている → 選び方は「比較の方法」、メリットは「読者にとっての効果」と角度を分ける
・選び方H3と注意点H3で同じ内容を書いている → 選び方は「判断基準」、注意点は「失敗パターンと対策」と角度を変える
・FAQが本文の既出内容の焼き直し → FAQは本文で扱っていないユーザーニーズに限定する
・1文目とstrong締めがほぼ同じ内容 → 角度を変える
・目的別セクションでサービスに触れる場合、紹介セクションと同じ情報で繰り返さない

## H. 記事テーマ別の差分ルール

### H-1. 総合比較記事（おすすめ18選等）
サービス数が多い（15〜20社）。選び方4項目 + メリット4項目 + 注意点4項目が標準。テーブル5行目は「お試しの有無」。

### H-2. お試しセット特化記事
「お試しセットとは？」のH2セクションが選び方の前に入る。テーブル5行目は「お試し内容」。紹介文はお試しセットの価格・内容・割引率に重点。

### H-3. 離乳食特化記事
メリットセクションが「離乳食に食材宅配を利用するメリット」になる。月齢対応・アレルギー配慮の観点。サービス数は8社程度。

### H-4. 安さ特化記事
選び方が「安さ」の観点に特化。価格の具体的な数字を多く盛り込む。

### H-5. 一人暮らし特化記事
選び方が「一人暮らし」の観点に特化。紹介文で一人暮らしとの相性に触れる一文を必ず入れる。

### H-6. ミールキット特化記事
「ミールキットとは？」のH2セクションが選び方の前に入る。調理時間・品数に触れる一文を必ず入れる。

## I. 訴求設計のルール

### I-1. CTA配置の基準
訴求サービスは紹介セクション以外でもCTAを配置してよい。ただし解説セクションでは1セクションにつき最大2社まで。

### I-2. 訴求社 vs 非訴求社の分量バランス
訴求サービスは150〜250字で丁寧に紹介。非訴求サービスは100〜180字で簡潔にまとめる。

### I-3. 訴求順位に基づく露出バランス
訴求順位が高いサービスほど露出を多くする。1社が3箇所以上に登場する場合は他社の露出を確認。
