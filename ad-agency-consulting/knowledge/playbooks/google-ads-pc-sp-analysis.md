# Google広告 PC/SP差分析プレイブック

**目的**：PCとSPでパフォーマンス差が出たときの標準分析手順。
**前提**：「SPがCV低い → LP最適化が原因」のような単一仮説で結論を出さず、複数仮説を網羅して検証する。

---

## 全体フロー

```
1. データをフラットに記述（PC/SPの数値を比較表で）
2. 何が違うかを列挙（CPC・CTR・CVR・CPA・CV絶対数）
3. 仮説を5つ網羅
4. 各仮説をデータで検証
5. 成立した仮説に対してアクションを設計
6. アクションを優先度順に並べる
```

## ステップ2：何が違うかを列挙

PC/SPの差を以下のパターンで分類：

| パターン | PC | SP | 示唆 |
|---|---|---|---|
| クリック取得能力 | CPC高・CTR高 | CPC低・CTR低 | SP配信は安いが刺さっていない |
| クリック取得能力 | CPC高・CTR低 | CPC低・CTR高 | PC配信が割高、SPは効率良い |
| CV変換 | CVR高 | CVR低 | LP・フォーム・計測のいずれかにSP問題 |
| CV変換 | CVR低 | CVR高 | SPで計測重複 or PC LPに問題 |
| ボリューム | CV多 | CV少 | SPの配信量・配信先・オーディエンスの問題 |

## ステップ3：仮説を5つ網羅

PC/SP差分析では、以下5仮説を**この順で**検証する：

### 仮説1：計測の問題 ★最優先

- SPでタグ発火が欠けていないか
- クロスデバイスCVがPC側に寄っていないか
- 電話CV・LINE CVなどSP優位なCVチャネルが計測されているか
- CV重複（同一ユーザーが複数CV計上）の有無

**検証方法**：
- Google Ads 「目標」 → コンバージョンアクション一覧 → 各CVのデバイス別発火数
- GA4 → イベント → デバイス別の発火数
- 電話番号CV（着信計測）の設定確認
- 営業側に「実際の問い合わせ流入経路」をヒアリング

**B2B特有の注意**：
税理士・経理代行のような業種は、SPユーザーが**フォームではなく電話してくる**ケースが多い。電話CVを設定していない場合、SPのCVは構造的に過小評価される。

### 仮説2：検索意図の差

- PCは取引意図が高い（業務時間中に法人検索）
- SPは情報収集寄り（移動中・休憩中の比較検討）

**検証方法**：
- 検索語句レポートをデバイス別にエクスポート
- 各語を以下に分類：
  - 指名検索（社名・サービス名）
  - 準指名（「税理士+地名」「経理代行+業界名」）
  - 取引意図（「依頼」「相見積もり」「料金」）
  - 情報収集（「とは」「比較」「違い」「方法」）
- PC/SPで構成比を比較

### 仮説3：LP・フォームのSP最適化

- 表示速度（PageSpeed Insights SPスコア）
- ファーストビューの訴求がSPで適切か
- フォーム入力のしづらさ
- コンテンツ並び順（PCは横並び、SPは縦並び）
- CTAボタンの位置・サイズ

**検証方法**：
- PageSpeed Insights SPスコア（80以上が目安）
- GA4 デバイス別の直帰率・滞在時間・スクロール深度
- フォーム到達率・フォーム送信率（ヒートマップツールあれば）

### 仮説4：オーディエンスの差

- SPが若年層に寄って、CVしない年齢帯を含む
- PCが法人IPからのアクセスが多い

**検証方法**：
- デバイス×年齢のクロス集計
- 年齢別CPA・CV
- （Google Analytics）法人/個人ユーザーの推定

### 仮説5：キャンペーン構造の相違

- PC/SPで同じKW・マッチタイプ・入札になっているか
- 同じLP（バリエーション含む）になっているか
- 同じ配信スケジュールか

**検証方法**：
- 両キャンペーンの設定を突き合わせ
- 構造が違う場合、比較自体が成立しない

## ステップ5：アクション設計

仮説の検証結果から、以下優先度でアクションを並べる：

| 優先度 | 条件 | アクション例 |
|---|---|---|
| 🔴 高 | 計測欠落確定 | 即タグ修正（広告判断より計測修正が先） |
| 🔴 高 | 構造相違あり | キャンペーン揃えて再比較 |
| 🟡 中 | SP LPO候補 | SP版LP改善（FV・フォーム・速度） |
| 🟡 中 | オーディエンス除外 | 18-24歳除外 |
| 🟢 低 | 入札調整 | デバイス別入札調整（-50%等） |

### アクション記述形式

各アクションは以下4要素で記述：

```
- 何を：（具体的に）
- どれくらい：（数量）
- いつまでに：（期日）
- 成功基準：（数値で）
```

例：
- 何を：SP版LPのFVを「料金訴求」から「相談無料訴求」に変更
- どれくらい：FV1パターン
- いつまでに：5/22
- 成功基準：SP CVR 0.3% → 0.6%（PCの50%水準まで回復）

## アンチパターン

| ❌ NG | ✅ 修正 |
|---|---|
| 「LPがモバイル最適化できていない」と即断 | 「LP最適化の可能性あり。ただし計測・検索意図差を先に確認」 |
| 単一仮説でアクション決定 | 5仮説網羅 → 検証 → 優先度順 |
| 計測確認をスキップ | 計測が最優先（広告判断より計測修正が先） |
| デバイス別入札調整だけで解決を試みる | 入札調整は最後の手段。構造・LP・計測を先に直す |
