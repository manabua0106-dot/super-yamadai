# /mtg-prep

次回定例MTGに向けて、数値・論点・想定Q&Aを揃える。

## 引数

- `$1`：クライアント名
- `$2`：MTG日付（省略時は最も近い未来日）

## 動作

### 1. 必読ファイル

- `clients/{client}/CLAUDE.md`
- `clients/{client}/feedback-log.md` ★最重要
- `clients/{client}/meetings/` の直近2回分
- `clients/{client}/data/snapshots/` の最新
- `knowledge/frameworks/multi-axis-analysis.md`

### 2. 数値準備（多軸分析チェックリスト）

以下が揃っているか確認。不足分はユーザーに取得依頼：

- [ ] 全体数値（直近30日 + 月初〜現在）
- [ ] 媒体×商材
- [ ] デバイス別
- [ ] 年齢別
- [ ] 性別
- [ ] 地域別
- [ ] 時間帯・曜日別
- [ ] キャンペーン×デバイス
- [ ] 検索語句×デバイス（Google）
- [ ] クリエイティブ別（Meta）

### 3. 前回MTGからの宿題確認

直前の `meetings/YYYY-MM-DD-summary.md` から TODO・宿題を抽出し、進捗を確認：

| TODO | 期日 | ステータス | 報告内容 |
|---|---|---|---|
| | | 完了 / 進行中 / 未着手 | |

### 4. 論点設計

今回MTGで報告・相談すべき論点を整理：

| # | 論点 | 報告内容 | 想定される質問 | 想定回答 |
|---|---|---|---|---|

### 5. 想定Q&A

クライアント側のプロが聞いてきそうな質問を事前に潰す：

| 想定質問 | 想定回答 | 必要データ | 準備状況 |
|---|---|---|---|

過去の `feedback-log.md` のクライアント発言パターンから推測する。

### 6. アジェンダドラフト

```markdown
# {クライアント名} 定例MTG（YYYY-MM-DD）アジェンダ

## 0. 全体数値サマリ（5分）
- 結論：

## 1. 前回宿題の進捗（5分）
- 

## 2. 今週の論点（20分）
2.1 
2.2 
2.3 

## 3. 来週のアクション（5分）
- 

## 4. 確認事項（5分）
- 
```

### 7. 出力

- `clients/{client}/meetings/YYYY-MM-DD-prep.md` に保存
- ユーザーに「準備完了。不足データはこれ」と提示
